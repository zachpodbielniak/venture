* For an AI agent

=skills/venturectl/SKILL.md= is a skill file written for an agent
driving this CLI: setup, the five traps that account for most mistakes, a
worked forge configuration, and the exit codes to branch on. It is
maintained alongside the code rather than as documentation about it.

Install it for whichever agents you use:

#+begin_src bash
make install-skill
#+end_src

That symlinks it into =~/.claude/skills=, =~/.grok/skills= and
=~/.agents/skills= — Claude Code, grok-build and opencode respectively.
Symlinked rather than copied, so editing the working tree is immediately
what every agent reads; a copy would drift the first time one was edited in
place. Override =SKILL_DESTS= for a different set, and =make
uninstall-skill= removes the links. Neither target will touch a real
directory that happens to share the name.

The habit it exists to instil is =venturectl describe TYPE= before writing
anything. That prints every field in the spelling you must type, what each
reference points at, and what each enum accepts — all generated from the
source, so unlike prose it cannot drift.

* venturectl

Drives the server over its REST API. It deliberately does not open the
database: one writer, one set of validation rules, one audit trail.

It links only =libventure-core.a= and yaml-glib, so =make venturectl= works on
a machine that cannot build the server at all.

* Setup

#+begin_src sh
export VENTURE_SERVER=http://127.0.0.1:8747   # the default
export VENTURE_TOKEN=vk_...                    # from POST /api/v1/tokens
#+end_src

The token is read from the environment rather than a flag because a flag is
visible in the process list. Keep it in =~/.bashrc-secrets=.

* Periods

Ledger reports accept =basis=cash= or =basis=accrual= and =dimension=VALUE= alongside the period; these options pass through to the same report implementation used by the web page.

Anywhere a period is accepted — a =report= argument, a =period== filter on a
list — the full grammar is:

| Form                     | Examples                                     |
|--------------------------+----------------------------------------------|
| named                    | =today=, =yesterday=, =this_week=, =last_week=, =this_month=, =last_month=, =this_quarter=, =last_quarter=, =this_year=, =last_year= |
| to date                  | =ytd=, =qtd=, =mtd=                          |
| fiscal year              | =fy= (current), =fy_2026=                    |
| rolling                  | =last_30_days=, =last_90_days=               |
| calendar                 | =2026=, =2026-03=, =2026-Q2=, =2026-03-14=   |
| explicit range           | =2026-01-01..2026-03-31=                     |
| everything               | =all=                                        |

* Output

A terminal gets an aligned table; a pipe gets JSON, so this works with no
flag:

#+begin_src sh
venturectl list sale | jq '.records[].gross.formatted'
venturectl -f yaml get venture 1 >> ~/Documents/notes/00_inbox/venture.org
venturectl -f csv list expense period=fy > expenses.csv
#+end_src

=--format= takes =table=, =json=, =yaml= or =csv=. =--quiet= drops the totals
line.

The table truncates and selects columns for the eye; CSV does neither — every
field appears, in the wire spelling =describe= documents, with money printed
as its formatted form. =-f csv report NAME= returns the server's own CSV
rendering, byte-identical to the web export. Cells are escaped and a leading
=​== is defused, so an export opens in a spreadsheet without executing
anything.

* Exit codes

Distinct so a script can branch:

| Code | Meaning              |
|------+----------------------|
|    0 | success              |
|    1 | general failure      |
|    2 | usage                |
|    3 | not found            |
|    4 | conflict             |
|    5 | authentication       |
|    6 | unsupported          |
|    7 | network or timeout   |
|    8 | validation           |

#+begin_src sh
if ! venturectl get venture "$id" >/dev/null 2>&1; then
	case $? in
		3) echo "no such venture" ;;
		5) echo "check VENTURE_TOKEN" ;;
		7) echo "server unreachable" ;;
	esac
fi
#+end_src

* Using it with an AI

The interface is deliberately machine-friendly: =venturectl types= enumerates
what exists, =venturectl types TYPE= describes a type's fields, and JSON is
the default when output is piped. An agent can discover the whole data model
without documentation.

For an agent that speaks the Model Context Protocol rather than a shell,
=venturectl mcp= is the same API as a stdio MCP server: nine tools whose
record-type enumerations are generated from =/api/v1/schema= at startup, so a
plugin's type is offered with no change anywhere. Writes are staged rather
than applied unless =--apply-writes= is given: the change is queued on the
server for somebody to approve, not merely described. =venturectl --stage=
does the same for =create=, =update=, =delete= and =act= from the shell. It takes its credential from
=VENTURE_TOKEN= and refuses =--token= outright, since an MCP server is spawned
from a config file. See [[file:mcp.org][venturectl mcp]].

* Reconciliation suggestions

=venturectl reconcile suggest TYPE ID [--matcher NAME] [--threshold N]=
prints ranked book-record matches for a saved bank line. Without =--matcher=
it merges every registered matcher. The default threshold is 80; scores
strictly above it stage the banking =match= action when that module
is available. With no banking records installed it returns suggestions
only. It never applies a match. Use =-f json= to include the full confirmation
objects, then review them in the ordinary confirmation queue. See
[[file:reconciliation.org][reconciliation suggestions]] for matcher plugins
and the banking seam.
* Stripe checkout

=invoice checkout ID= calls the Stripe service and returns the stored Checkout record, including =url=. It requires the Stripe module and a sent invoice with one configured product line. See [[file:stripe.org][Stripe payments]].
* Asset actions

=venturectl asset place ID=, =asset dispose ID proceeds=AMOUNT= and
=asset write-off ID= call the asset service. Optional =in_service_at= or
=disposed_at= selects an effective date.

=venturectl assets run-period YYYY-MM [organization_id=ID] [--dry-run]=
posts the organization's scheduled depreciation and deferral releases in
one transaction. The default organization is used when omitted. A retry
posts only remaining scheduled entries; a closed period is refused.

The ordinary record commands manage draft =fixed_asset= and new =deferral=
records. Lifecycle status and schedule history are service-owned. See
[[file:assets.org][fixed assets and deferrals]] for profiles and examples.
* Organization access and journal posting

The ordinary =list/get/create/update/delete/describe= commands also manage
=organization_membership=, =team= and =team_membership=. Tokens constrain all
responses to their mint-time memberships intersected with current authority.
Selecting =organization_id= only narrows that scope. Global owners keep the
existing output formats and data authority.

=venturectl journal post ID= calls the shared posting service. An organization
editor receives a pending confirmation; finance and organization admin/owner
can post directly. =venturectl --stage journal post ID= always proposes.
A pending confirmation is not a posted journal. Generic =update journal=
cannot advance state. See [[file:orgaccess.org][Organization access]].

venturectl billing pause 1

venturectl billing renew --as-of 2026-04-01

* Headline metrics

No new verb: the headline reports run through =report=, and the
per-organisation settings are an ordinary record type. Definitions are in
[[file:reporting.org][Reporting]].

#+begin_src sh
venturectl report cac 2026-Q1
venturectl report cac 2026-Q1 venture_id=2 as_of=2026-03-15
venturectl report customer_churn this_month days=60
venturectl report ltv this_year organization_id=1
venturectl report ltv_cac last_quarter
venturectl report customer_cohorts this_year
venturectl create headline_setting organization_id=1 'hourly_rate=45 USD' \
  minimum_customer_months=6 activity_days=60
venturectl update headline_setting 1 classic_home=true   # / back to the old dashboard
venturectl update expense 42 acquisition=true             # count it in CAC
venturectl update expense 43 cost_of_revenue=true         # count it against gross margin
venturectl update expense 44 campaign_id=3                # a campaign's recorded cost
#+end_src

=renew= without an ID sweeps all due subscriptions in the selected
organization; =renew ID= renews one. =--as-of= sets the effective action
or sweep date. =--dry-run= previews sweeps without writing anything.
The generated =plan= and =plan_price= records configure the catalogue.
Direct subscription state writes are refused. The assistant can stage
=billing_request= through its generated create tool; all CLI billing
actions also honor =--stage=. See [[file:billing.org][SaaS billing]] for prices,
trial activation, proration, historical report definitions and limitations.
* Transactional mail

=venturectl mail send to=... subject=... body=...= enqueues; =--html FILE=
adds HTML. =mail test to=...= tests the configured SMTP transport immediately.
=mail deliver [--limit N]= sweeps due messages, =mail list state=uncertain=
shows outcomes needing an operator, and =mail retry ID= deliberately reuses
that row and Message-ID. All accept =organization_id=N= where relevant.
See [[file:mail.org][mail]] for uncertainty and scheduling. Actions reject
=--stage=; =--stage create mail_message= proposes an enqueue instead.

=venturectl mail sync [organization_id=N] [limit=N]= runs the bounded
inbound sweep over every active =mail_account= in the organization that is
not backing off and prints the accounts and messages processed, the accounts
skipped, whether a budget deferred the rest, and any per-account error.
=venturectl mail sync account_id=N= syncs one account now, ignoring its
backoff (owner only). =venturectl mail contact ID= turns an unmatched sender
into a contact and backfills its earlier mail onto the timeline;
=venturectl mail dismiss ID= keeps the address as an ignore-list entry. The
raw messages, interactions, unmatched senders and capture items the sync
creates are ordinary records: =venturectl list mail_inbound=, =venturectl
list mail_unmatched_sender dismissed=false=. See [[file:mail.org][mail]],
section Inbound.

* Quote actions

=venturectl quote send ID= freezes and queues a proposal.
=venturectl quote accept ID 'by=Full Name'= accepts it and issues its invoice.
=venturectl quote decline ID 'reason=Explanation'= records a refusal;
=venturectl quote revise ID= clones the proposal and supersedes its source.
For approval, use =--stage create quote_action quote_id=ID action=accept
expected_version=N accepted_by=NAME=. See [[file:quotes.org][quotes]].
* Leads

=venturectl lead convert ID [deal=yes|no] [company_id=ID] [contact_id=ID]=
converts a qualified inquiry atomically. =--stage= queues conversion for
approval. =venturectl lead reassign ID [owner=NAME]= assigns explicitly or
runs matching rules again. Generic =create/update lead= supports capture and
qualification; converted state and references belong to the service.
Recycle with =status=recycled unqualified_reason=... recycle_until=YYYY-MM-DD=.
See [[file:leads.org][leads]] for capture forms, duplicate policies and reports.
* Planned activities

=venturectl activity complete ID outcome=...= completes planned work through
the activity service, records history and advances recurrence atomically.
=venturectl activity list mine|overdue|today= reads the signed-in user's worklist.
The existing =activity TYPE ID= still reads a record's timeline.
Create and edit planned work with generic =create activity= and =update activity=;
setting =status=done= through generic writes is refused. See [[file:activities.org][activities]].
* Vendor bills

=venturectl bill approve ID [date=DATE]= approves a draft supplier bill.
=bill pay ID [amount=MONEY] [date=DATE] [method=METHOD]= pays the outstanding
amount or the supplied partial amount; excess cash remains vendor credit.
=bill void ID [date=DATE]= reverses an unpaid approved bill. These call the
same =VenturePayablesService= as the web and REST actions. Generic writes
setting a bill's financial status are refused.

=report payables PERIOD= reconstructs historical aging;
=report vendor_statement PERIOD vendor_id=ID= reads the supplier's dated
statement. Both accept =organization_id=, =currency= and =as_of=.
See [[file:payables.org][vendor payables]] for credits and cash-report projections.

=bill pay-bulk 1,2,3 adapter=transfer= pays selected approved bills through
the payables adapters. =close open|run|sign|complete|reopen|pack= is the
accountant close workspace. =capture ingest|convert|reject= files receipts
and supplier invoices. =accounting= lists the daily books next actions.
See [[file:close.org][close]], [[file:capture.org][capture]] and
[[file:accounting.org][accounting home]].

=venturectl cutover template SECTION= prints a cutover CSV template;
=venturectl cutover csv source=S cutoff=DATE [currency=C] SECTION=@FILE ...=
sends CSV files to preview a new cutover batch (=build_only=true= returns the
payload JSON instead). Batch actions are ordinary record actions:
=act accounting_cutover ID import|reconcile|rollback_preflight|activate|rollback=.
See [[file:cutover.org][accounting cutover]].

=venturectl tax-filing prepare|review|submit|acknowledge|amend= prepares a
jurisdiction return pack. =contractor-tax prepare|review|approve|export=
builds a 1099-NEC pack from paid bills. See [[file:tax-filing.org][tax
filing]] and [[file:contractor-tax.org][contractor 1099]].
* Banking actions

=venturectl bank ACTION ID [JSON|@FILE]= calls the banking service over REST.
=import= takes a bank account ID; =auto= and =reconcile= take a statement ID;
=match=, =unmatch=, =exclude= and =create= take a transaction ID.
=venturectl bank match AUTO STATEMENT_ID= is the bulk exact-match action.
See [[file:banking.org][Banking]] for import mappings and action parameters.
* Sales pipeline actions

=venturectl deal move ID STAGE [NOTE]= moves a deal through
=VentureDealService=. STAGE is a =pipeline_stage= id in the deal's pipeline.
Fill its required fields and loss reason first with ordinary =update deal=.
Generic updates cannot change =stage=, =stage_id= or =closed_at=.
See [[file:pipelines.org][Sales pipelines]] for configuration and forecasting.
* Follow-up sequences

=sequence enroll ID contact_id=ID [field=value ...]= enrolls through the
sequence service. The ID names the sequence; other fields describe the
=enrollment=, including =deal_id=, =lead_id=, =owner_id= and
=enrollment_reason=. =--stage sequence enroll= proposes enrollment for
approval. The ordinary =create sequence_enrollment= path has the same
validation and supports the assistant's standard staged create tool.

=sequence run [--as-of ISO_TIMESTAMP] [organization_id=ID]= executes up to
1000 due enrollments in one organization, defaulting to the server's default
organization. A timestamp must carry its timezone. Omit it for now.
=sequence status ENROLLMENT_ID= reads the enrollment and its delivery history.
The command returns pending delivery rows; it does not send mail.

Configure sequences and their steps with ordinary =create= / =update=
commands after =describe sequence= and =describe sequence_step=. Sending
hours and weekdays are interpreted in the sequence timezone. See
[[file:sequences.org][follow-up sequences]] for checkpoints and the adapter contract.
* Record actions

=venturectl act TYPE ID ACTION [key=value ...]= discovers the action and
its parameter kinds from =GET /api/v1/schema/TYPE=, then sends the generic
action route. =--stage= proposes it for approval. Unknown names are refused.
For example: =venturectl --stage act journal 42 post=.

Journal actions are =post= and =reverse= (optional =occurred_at= and =memo=).
Type-level =create_and_post= uses ID zero and a =journal= JSON-text parameter
containing the header and =lines= array. All three support =--stage=.

=venturectl --help= includes =act= among the commands accepting =--stage=.

* Backfilling journals

=venturectl post backfill [organization_id=ID] [--dry-run]= posts missing
current sale/expense versions through the automatic-journal service, in date
order. It requires an editor and the =autojournal= module. Omission selects
the default organization. The response reports candidates, posted and skipped
incomplete documents. A dry run validates the complete batch and rolls it back.
See [[file:autojournal.org][automatic journals]] before cutting over legacy books.
* Ledger statements

#+begin_src sh
venturectl report balance_sheet 2026-08 organization_id=1 currency=USD
venturectl report income_statement 2026-08 organization_id=1 currency=USD compare_to=2026-07
venturectl -f csv report general_ledger 2026-08 organization_id=1 currency=USD account_id=1
#+end_src

The =statements= reports accept =compare_to= for a prior period, =as_of= for
an accounting cutoff, and one =organization_id= and =currency=. General
ledger optionally accepts =account_id=. See [[file:statements.org][financial statement definitions]].
