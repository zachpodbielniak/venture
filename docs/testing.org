* Testing

#+begin_src sh
make DEBUG=1 test                    # everything
make DEBUG=1 test-one T=test-money   # one binary, verbosely
make DEBUG=1 test-valgrind           # under valgrind, if installed
#+end_src

Every test runs against a private in-memory SQLite database, so the suite needs no external service. It leaves nothing behind on disk either -- see [[#temporary-directories][Temporary directories]] below, which is a claim the suite now checks rather than one this page merely makes. Set =VENTURE_TEST_DB= to a =postgres://= URI to run the database tests against PostgreSQL instead:

#+begin_src sh
podman run -d --rm --name pg -e POSTGRES_PASSWORD=t -e POSTGRES_USER=venture \
    -e POSTGRES_DB=venture -p 127.0.0.1:55432:5432 postgres:16-alpine
VENTURE_TEST_DB=postgres://venture:t@127.0.0.1:55432/venture \
    ./build/debug/tests/test-database
#+end_src

Each test drops and recreates the schema before it runs. An external database is one shared database for the whole run, and several tests create a venture with the slug "books" -- a UNIQUE column -- so without that reset the second one fails for a reason that has nothing to do with what it tests. Worth knowing what that hid: the PostgreSQL run used to stop at the ninth test, and the money-summation bug behind it went unnoticed because SQLite returns =SUM()= as an integer while PostgreSQL widens it to numeric.

The whole tree builds with =-Werror= and a wide warning set in =gnu89=. A warning is a latent bug; there are none.

* What the suite pins down

** =test-money=

The cases correspond to ways a naive money implementation loses real money: floating point that cannot hold a dime, rounding that biases upward, a split that drops a cent, a zero-decimal currency inflated a hundredfold, silent overflow, and a tolerant parser that must still reject garbage.

** =test-entity=

The base class is generic, so a bug in it is a bug in every record type at once. These pin down that declarative fields really store values, that JSON round-trips, that an absent member leaves a field alone (which is what gives PATCH semantics), that sensitive fields are omitted rather than nulled, that a diff redacts them, and that the derived money figures — net, deductible, weighted, ROI, idea score — are computed the way the reports expect.

** =test-config=

Most importantly, that the YAML document compiled into the binary actually parses and maps onto every property. Without that test the shipped defaults could silently diverge from the C table and nobody would notice until a setting failed to take effect.

Also that validation refuses a non-loopback bind address with authentication off. That combination is not a configuration choice.

** =test-database=

Round-tripping through both backends, optimistic concurrency detecting a lost update, soft deletion hiding but keeping, the audit trail recording the prompt behind an AI change, the ledger refusing an unbalanced transaction, and the schema gaining a column without a hand-written migration.

Two tests exist specifically to prove injection is impossible: a filter naming a field that does not exist is refused, and a hostile *value* is bound as a parameter and simply matches nothing — with the table still there afterwards.

** =test-report=

The arithmetic against known data, not merely that reports run. Also that an unreviewed expense counts as zero in the tax report and that the report says so, that CSV export defuses spreadsheet formula injection, and that HTML export escapes its content.

** =test-receivables=

Receipts, partial and complete allocations, deposits, credit notes and
refunds; external IDs unique within an organization; immutable financial
history; and the lifecycle signal's veto. Failures injected after a source
write must leave every record and audit entry unchanged. Web, REST, the
real =venturectl= process and its MCP tool produce identical financial
rows, including a staged tool call applied after approval. Each source
operation produces a balanced ledger batch. Historical balances and aging
use dated events, including the exclusive month-end boundary. The module
switch hides its records, reports and settlement actions together.

In a sandbox without a writable dconf runtime directory, run the suite
with =GSETTINGS_BACKEND=memory=. Leave =VENTURE_TEST_DB= unset for SQLite;
that variable selects the external PostgreSQL fixture and its schema reset.

** =test-auth=

The tests where a failure is a security hole. That the three login failure modes — wrong password, unknown user, deactivated account — are textually identical, so the form cannot be used to enumerate accounts. That a token stores only a hash. That password hashes are salted and the iteration count is floored. That comparison is constant time.

** =test-plugin=

The claim under test is that an extension is indistinguishable from a
built-in. The example plugin is loaded for real, and its record type is then
expected to have a table, a registry entry and a round-trip through the
database, while its report is expected to appear in the same registry every
consumer reads. =make test= builds the plugins first so this cannot silently
skip.

Also that one broken plugin or venture type is skipped rather than taking the
server down with it, that a plugin named in =plugins.required= is fatal when
missing, and that loading the same file twice registers it once — two
configured directories can overlap.

The crispy path is exercised for real: a =.c= file is written to a plugin
directory, compiled on demand, loaded, and its report generated. The probe
plugin deliberately uses the reporting engine, which is only visible with
=VENTURE_SERVER_BUILD= defined — a regression in the flags the crispy host
passes would otherwise surface as a baffling failure in somebody's own
plugin instead of here. That is not hypothetical: the flags were wrong until
this test was written.

For automation: the handlers are exercised through
=venture_automation_invoke()=, including that a handler's writes are audited
as the automation rather than as whoever was logged in, and that an audit
entry never raises an event — the check that stops a rule that writes from
triggering itself forever.

** =test-entity=, on generated surfaces

That the declared field order and the declared field kind both survive into
the spec every generated surface reads. Neither can be recovered from the
GObject property: properties come back in their own order, and a long text
field is the same C type as a short string one. Both were lost at some point,
and neither looked like an ordering or declaration problem — one showed up as
a list of empty columns, the other as a Notes box one line tall.

** =test-auth=, on chat conversations

That a stored conversation is readable only by the account that had it: the
other account gets /not found/ — indistinguishable from a thread that never
existed, which matters because thread ids are sequential — and its resume
list does not mention the thread. Also that the generic =/api/v1/chat_*=
surfaces are owner-only, so the scoping cannot be walked around, and that
every chat route refuses anonymous callers.

** =test-database=, on the chat transcript

That messages come back in insertion order with the role enum intact. A
transcript is replayed to the model when a thread resumes; if the role did
not survive, a resumed conversation would replay the assistant's words as
the user's — nothing crashes, the conversation just quietly becomes
nonsense.

** =test-entity=, on the CRM and ticket shape

That a contact points at a company by reference rather than naming one in
text — the free-text version could not answer "everything to do with this
account" and spelled the same company three ways. That one ticket type
carries both internal work and external requests. That a comment's internal
flag survives, since it is the reason a comment is a record at all.

** =test-ticket-relation=

That a ticket can point at any registered type, and that a pair which cannot mean anything is refused before it is written: an unknown type name, an id that is not there, the same pair twice, and a ticket related to itself. Also that the reverse lookup works, since a polymorphic pair is invisible to the machinery that finds records pointing at this one — and that a deleted subject leaves the relation still readable.

** =test-module=

That the built-in module table is in dependency order and every rule of registration holds; that a module whose requirement is off is refused with both named, and that the legacy =*.enabled= switches still count; that a disabled module's types and reports vanish from the registries and its pages, API routes and schema entries answer 404 over a real server, while the sidebar loses the links and the heading; that a written reference into a disabled module is refused with the switch named; and that a plugin's module resolves against the running configuration the moment it is added.

** =test-record-link=

That any two records of any types link, and that one row reads correctly from both ends -- the kind from the source, the inverse from the target. That a link which cannot mean anything is refused: an unknown type, a missing record, a record linked to itself, the same pair twice in either direction, the audit log. That the checks run at the save and not only in the constructor, so a link built by hand -- as the generic API would -- is held to them and gets its labels filled in. That a deleted or switched-off end keeps its label and loses its link.

** =test-factory=

That a =workflow_run= delivery becomes a build when requested and updates the same build when completed, a retried delivery included, and that a bad signature plants nothing. That a release cut on the forge becomes a release here with its version read from the tag, and a deleted one is yanked on the same row. That the changelog is drafted from the tickets by issue type and never overwrites what somebody wrote unless asked. That the lead-time and incident reports measure what they claim. That with the module off every page, type and report is gone and the CI webhook is acknowledged and dropped -- and that flipping the switch on the live configuration is enough to bring it back.

** =test-dashboard=

That the dashboards module owns its two types and the widget catalogue has every built-in kind, with the factory ones marked as its. That a plugin can add a kind and a bad or duplicate one is refused. That a slug is derived, normalised and unique. That a widget is refused at the save for a kind, a type, a report or options that do not exist, and accepted for a type or report whose module is merely off. That count, list and breakdown answer from the same rows, with ={me}= substituted for whoever is looking; that a note's markup is escaped and an action with a script href is dropped; that metric, report and chart read one report three ways; that a widget for a module that is off, or of a kind that vanished, is an error in place and never a missing page. That only one dashboard is home, and a personal home is nobody else's. That every template imports, an export re-imports to the same definition, importing twice gives two, and a definition with one bad widget leaves nothing behind. And, over a real server: the whole loop from template to home page to deletion, that another user's personal dashboard answers 404 on the page, the API and the fragment, and that the module switch takes the pages, the API and the sidebar entry with it and leaves =/= as the built-in overview.

** =test-webhook=

Webhooks out, routing, satisfaction and triage. An event is named from the type and the action, and the patterns a webhook subscribes to match exactly, per-type or everything — and =ticket.*= does not swallow =ticket_link=. A change reaches a real HTTP server the test owns, carrying a body whose HMAC the test recomputes, and the delivery is recorded; a webhook subscribed to something else receives nothing, and saving a webhook fires nothing. Ten refusals switch it off and it goes quiet. A rota assigns in turn and does not override a ticket raised for somebody, the narrowest rule wins, least-busy counts, and a rule naming nobody refuses. The support report scores satisfaction over the ratings given. Applying a triage takes what it understands, merges tags rather than replacing them, and ignores an invented priority.

** =test-desk=

The workdesk. The inbox is fed by the audit trail and nobody is told about their own edit: an assignment tells the assignee, a comment tells the mentioned and the watchers, a change tells the watchers what moved, the system's roll-ups tell nobody, and reading is per person. A service-level policy matches most-specific-first, stamps a ticket's clocks once, is stamped by the first visible reply and not by a note, and the sweep marks a breach once. A macro applies in one transaction and an inactive one is refused; worklogs roll up onto the ticket and follow a removal; a sprint counts its points; a bulk edit is all or nothing; the timeline weaves changes, comments and worklogs newest first; a budget warns once and refuses a run once exhausted; an incident opens its fix once, linked; the delivery report reads the four keys.

** =test-forge=

Rule resolution in every direction, including that no rule means nothing runs and that a disabled rule falls through to a broader one. Branch names built from hostile titles are still legal git refnames and cannot be read as command-line flags. The Forgejo client refuses a non-http origin, refuses to follow a redirect (a redirect would carry this install's access token to a host the response chose), escapes repository names so they cannot walk out of the path, and maps status codes onto errors an operator can act on. Webhook signatures: correct, wrong, computed over a different body, absent, and — the one that matters — a forge with no secret configured, which must be refused rather than trusted.

** =test-work-sandbox=

The confinement the in-process runner rests on. Paths inside the workspace resolve; every way out is refused, including =..=, absolute paths, symlinks created during the run, and a sibling directory whose name merely starts with the workspace's. That last one is the classic prefix-match bug and it is the shortest route out of any sandbox. Also asserts the executor offers no shell — by calling =bash= and requiring an error, not by reading the tool list.

** =test-work-service=

That runs are off unless the operator turns them on, that starting one returns while it is still live rather than blocking the main loop, that a ticket with no rule refuses, and that a run left in flight by a previous process is reconciled to =interrupted= rather than resumed.

** =test-automation=

That pod handlers run on the thread that dispatched them. podomation's default handler timeout selects an async dispatch path that runs a synchronous handler on a worker thread while the caller blocks in a nested main loop — and VENTURE's handler writes to the database and reads a cascade guard that is not atomic.

* Adding tests

The =test-ledger= binary pins the universal posting boundary, including
outer-transaction rollback, veto signals, source-save integration, exchange
valuation, immutable history and authoritative balances. The native plugin
test also posts with the example plugin's real rule. See
[[file:ledger.org][the general journal]] for the contracts under test.

One file per subsystem, =tests/test-<area>.c=, picked up automatically by the Makefile's wildcard. Use the fixture pattern for anything needing a database:

#+begin_src C
g_test_add("/area/behaviour", Fixture, NULL,
           fixture_set_up, test_behaviour, fixture_tear_down);
#+end_src

Write the test around the behaviour that matters rather than the function that implements it, and say in a comment what breaks if it regresses. Several tests in this suite exist because a plausible implementation would have been wrong in a way that only shows up in a tax return.

** Temporary directories
:PROPERTIES:
:CUSTOM_ID: temporary-directories
:END:

A fixture that needs a state directory makes one with =g_dir_make_tmp()= and removes it with =venture_test_remove_tree()= from =tests/venture-test-util.h=. Never =g_rmdir()=, and never =g_file_delete()=: both do nothing at all to a directory that is not empty, and both report it in a way every caller here discarded. So a fixture that wrote a single file inside the directory it made left that directory behind, silently, once per test per run.

Five fixtures did. A full green suite left seventeen directories in =/tmp=, 44 had accumulated over a few hours of ordinary runs, and "All 14 test binaries passed" said nothing about any of it.

=venture_test_remove_tree()= deletes the tree, and checks the canonical path of every entry against the root it was given before touching it -- so a =..= in a name, or a directory reached through a symlink, cannot carry a teardown outside the directory the fixture made. A symlink is unlinked rather than followed, and it is the link's own location that is checked, not where it points.

=make test= gives each run a private =TMPDIR=, which =g_get_tmp_dir()= honours, and =tools/venture-test-litter.sh= compares the directories before the run against the ones after it. A *green* run that left one is a failure:

#+begin_src text
test-litter: the suite passed but left temporary directories behind:
  /tmp/venture-run-YOlWIW/venture-routes-CJ5AV3
test-litter: a fixture removed its file and not the directory holding it
test-litter: use venture_test_remove_tree(), not g_rmdir() or g_file_delete()
#+end_src

It compares the run against itself rather than checking that =/tmp= is empty, because a *failing* run leaves its directories on purpose. A =g_assert= failure aborts the process, so no teardown runs on that path -- which is correct and should stay that way: that directory is the evidence. The private =TMPDIR= is what makes the comparison exact, since two worktrees building at once would otherwise report each other's fixtures.

What it cannot see is a directory whose name is not a =g_dir_make_tmp()= string literal in =tests/test-*.c=; the prefixes are read from those literals rather than written down, so the list grows with the suite instead of drifting from it. =make test='s bare =rmdir= of its own =TMPDIR= is the second net: it succeeds only on an empty directory, so a run that left something under a name the scan cannot match still leaves its =TMPDIR= where somebody will find it.

One more thing it surfaced, which was not litter: =test-work-service= started a coding run and returned without waiting for it, so the service's worker thread was still calling =g_mkdir_with_parents()= for the run's workspace while the teardown was removing the directory above it. =strace= shows the =mkdir= and the =rmdir= interleaved. =settle_runs()= drains the live set first. A test that starts background work and walks away leaves a thread writing into a directory nobody owns any more, whoever wins the race.

* Standalone CLI dependency boundary

The CLI must build without the mail server's GMime development package. Run =make DEBUG=1 -W src/cli/main.c venturectl= without any temporary server dependency prefix to compile and relink the CLI. Server-only pkg-config queries are deferred until a server or test recipe expands its flags; a successful CLI build that still emits missing server-package diagnostics fails this boundary.

The Stripe sub-build consumes the YAML archive produced by the parent build. It must not recompile private YAML objects into that shared archive: a parallel =make DEBUG=1 -j4= may be linking =venturectl= against it. =YAML_OBJECTS== on the Stripe sub-make keeps archive ownership with =dep-yaml-glib= while retaining the declared archive prerequisite.

** =test-accounting-acceptance=

The independent replacement pack: a synthetic business issues a taxed invoice,
takes a partial receipt, records and pays a bill, and keeps subledgers tied to
the GL. Rollback and retry leave no partial money. It does not claim country,
payroll or inventory parity. Invoice detail, cash-basis reports, bank reopen
and the cutover wizard are asserted over HTTP in the module suites.

** =test-cutover=

Preview lists unsupported source fields, import is idempotent on source IDs,
reconcile checks trial balance and opening AR/bank totals, rollback reverses
opening cash and voids imported invoices, generic writes are refused, and the
Cutover page plus preview/action routes are covered over HTTP.
