* What this is

The =blizzard-auctions= plugin turns Blizzard's Game Data API into a VENTURE data source: every connected realm's auction house and the region's commodity market, hour by hour, into the source's series store, where the Trading pages browse it, alerts watch it and the arbitrage scan prices flips, crafts and dropship-style buys between realms. It also reads the crafting professions into recipe records, prices auction-house fees, and exports a scan's items as a TradeSkillMaster group.

It is the reference example of a native plugin that reaches several extension points at once; [[file:../plugins.org::*The reference plugins][Plugins: the reference plugins]] walks through the code, and [[file:../market-data.org][Market data]] covers the machinery it plugs into -- the feeds module, the worker thread, the series store and the Trading pages. This page is the operator's side: what to set up, in what order, and what to expect.

Nothing about World of Warcraft is in VENTURE's core. Venues, instruments, listings, fee models and export formats are generic; this plugin is what knows a realm, a bonus id and copper.

* Before you start

You need a Battle.net API client: sign in at =develop.battle.net=, create a client, and keep its *client id* and *client secret*. The id is not a secret; the secret is, and VENTURE seals it.

| Need                         | Why                                                                                                    |
|------------------------------+--------------------------------------------------------------------------------------------------------|
| the plugin loaded            | it is built into =plugins-optional/=, which nothing loads by default                                   |
| =feeds.enabled: true=        | the feeds module is off by default                                                                     |
| the API origins allowlisted  | =feeds.allowed_origins= is deny by default                                                             |
| a =GOLD= currency, exponent 4 | Blizzard prices are copper, a ten-thousandth of a gold; the plugin refuses to run against anything else |
| the =marketdata= module      | on by default: venues, instruments, browsing                                                           |
| =production= and =arbitrage= | on by default: recipes, the scan, the fee model's use                                                  |

* Turning it on

In the configuration (see [[file:../configuration.org][Configuration]]):

#+begin_src yaml
plugins:
  paths:
    - /usr/local/lib64/venture/plugins-optional

feeds:
  enabled: true
  allowed_origins: https://us.api.blizzard.com,https://oauth.battle.net,https://render.worldofwarcraft.com
#+end_src

Use the region's API origin: =https://eu.api.blizzard.com=, =https://kr.api.blizzard.com= or =https://tw.api.blizzard.com=. The token endpoint is =https://oauth.battle.net= for every region. From a build tree, =VENTURE_PLUGIN_PATH=build/debug/plugins:build/debug/plugins-optional= loads it without installing. The server's log says =Loaded plugin .../blizzard-auctions.so=, and =/api/v1/arbitrage/registries= lists =wow_auction= and =tsm=.

* The currency

The plugin emits prices in the currency its settings name, =GOLD= by default, and never registers one itself: a currency is a record an organization owns, and a worker thread must not write records. Register it once, as an administrator, with its coins so amounts read the way the game shows them:

#+begin_src sh
venturectl create currency code=GOLD name=Gold kind=virtual exponent=4 book_treatment=separate_book \
    symbol_position=suffix \
    denominations='[{"suffix":"g","units":10000},{"suffix":"s","units":100},{"suffix":"c","units":1}]'
#+end_src

=separate_book= keeps gold in a journal of its own; see [[file:../currencies.org][Currencies]] and [[file:game-economy.org][the game economy example]]. With exponent 4, a price of 12345 copper is =1.2345 GOLD= -- =1g 23s 45c=. A source whose currency is not registered, or registered with another exponent, fails its run with a message saying exactly this.

* The data source

#+begin_src sh
cat > settings.yaml <<'EOF'
region: us
client_id: 0123456789abcdef0123456789abcdef
connected_realm_ids: []        # every realm of the region, found from its index
include_commodities: true
requests_per_hour: 36000
EOF

venturectl create data_source name="US auction houses" provider=blizzard_auctions \
    schedule=auto currency=GOLD venue_namespace=us-realm instrument_namespace=wow-item \
    "settings=$(cat settings.yaml)"
#+end_src

Then set the client secret on the source's credentials page, =/feeds/ID/credentials= (owner or administrator): it is sealed in the integration store as =feed-<uuid>=, never shown again, and refused if typed into the settings. The settings, all optional except =client_id=:

| Setting                | Default                          | Meaning                                                                                                                       |
|------------------------+----------------------------------+-------------------------------------------------------------------------------------------------------------------------------|
| =region=               | =us=                             | =us=, =eu=, =kr= or =tw=: the API origin, the namespaces and every venue's group                                                |
| =client_id=            | none                             | the Battle.net client's id                                                                                                    |
| =client_secret=        | --                               | *credential*: set on the credentials page, never here                                                                         |
| =connected_realm_ids=  | empty                            | connected realm ids, each its own unit; empty: every realm the region's index lists, each its own unit all the same (below)   |
| =include_commodities=  | =true=                           | the region-wide commodity market as a unit                                                                                    |
| =include_bid_only=     | =false=                          | list an auction with a bid and no buyout at its bid; off, it is skipped, since it cannot be bought now (see the price below)   |
| =currency=             | =GOLD=                           | the registered currency, exponent 4, prices are emitted in                                                                    |
| =locale=               | =en_US=                          | the locale item and realm names are asked in                                                                                  |
| =item_names_per_fetch= | 100                              | item detail lookups one fetch may make, 0 to 5000 (0 for none); see the budget below                                          |
| =realm_index_hours=    | 24                               | with no realms listed, how old the known realm list may grow before the index is read again, 0 to 168 (0: every check)        |
| =key_modifier_types=   | every type                       | the modifier types that make an item a variant (see the key format below)                                                     |
| =requests_per_hour=    | 36000                            | the hourly budget; Blizzard allows 36,000 per client, and the schema's default applies when the setting is left out |
| =dynamic_namespace=, =static_namespace= | =dynamic-<region>=, =static-<region>= | overrides, for a classic realm (=dynamic-classic-us=) or a test                                               |
| =api_base=, =oauth_base= | the region's, =https://oauth.battle.net= | origin overrides, for a scripted test server; honoured only with =feeds.allow_endpoint_overrides= on (test and development), and still held to =feeds.allowed_origins= |

=act data_source ID test unit=11= fetches one unit and says what came back, writing nothing.

* Units, schedule and budget

Each unit is fetched on its own schedule. With =schedule: auto=, a unit is checked 45 seconds before its learned update time -- Blizzard publishes a realm's auctions about hourly -- with =If-Modified-Since= from the last =Last-Modified=, and a 304 costs no parsing. A manual sync asks for everything regardless.

| Unit                  | Fetches                                     | Budget cost |
|-----------------------+---------------------------------------------+-------------|
| a connected realm id  | =/data/wow/connected-realm/{id}/auctions=    | 1           |
| =commodities=         | =/data/wow/auctions/commodities=            | 25          |
| =realm-index= (no ids set) | =/data/wow/connected-realm/index=, once every =realm_index_hours= | 1 a day |

*The commodity market costs 25, even when it answers 304.* Blizzard charges it either way, so the budget is spent before the request goes out and never refunded. A source polling commodities every hour spends 600 of its 36,000. Name lookups, the token and a realm's name cost 1 each. A unit that would overspend the hour waits for the next one (the run says =deferred=); a 429 is honoured with its =Retry-After=.

** Every realm: leave the list empty

With =connected_realm_ids= empty the source finds the region's realms itself, and each is a unit of its own -- its own schedule, checked 45 seconds before its own snapshot is due. The units are named exactly as a listed id would be (="3676"=), so a realm's =If-Modified-Since=, its learned update time and its venue are the same whichever way the source names it, and switching a source from a list to empty (or back) loses nothing.

The =realm-index= unit reads the index and keeps the list in the plugin's cache, =<state_dir>/plugin-cache/blizzard-auctions/realms/=, one file per API origin and namespace. It asks Battle.net only when the list is older than =realm_index_hours= (a day); otherwise it answers "not modified" for free. When the list changes -- the first read, a realm Blizzard adds, one it merges away -- the run says =the index lists N connected realms (N new, N gone)= and the source is frozen again with a unit per realm. A failed read of the index fails only that unit: the last list goes on serving, across restarts too.

A brand-new source (or a new region) has no list yet, so its first pass is =realm-index= (and =commodities=) alone; the realms follow from the next pass, a moment later.

Listing ids is for reading /some/ realms. (Before 0.3.0 an empty list was one =realms= unit that walked the region ten realms with new data a fetch, so a realm's prices were up to eight hours old; =realms_per_fetch= belonged to it and is now ignored.)

** The budget

Blizzard allows 36,000 requests an hour per client. A region of ~85 connected realms polled adaptively costs about 85 to 350 an hour (one per snapshot, a few more when a check comes before Blizzard publishes), the commodity market 600, the index one a day, and the token and realm names a few after each refreeze. That leaves some 35,000 an hour for item names. A name costs up to three: the item, its media, and the icon from the CDN the first time any item uses it. =item_names_per_fetch= bounds them per fetch, and every realm unit is a fetch: at 5000, one fetch with a cold cache may spend up to 15,000 and the next few the rest of the hour, after which units wait (=deferred=) for the next. The names are shared by all of a source's units and kept in the store, so this is the first hours of a new source only. 1000 is a good setting for a whole region; 5000 names a fresh one in an hour or two at the cost of those hours' realm checks.

* What lands in the store

- *Venues*: one per connected realm, keyed by its id, named from =/data/wow/connected-realm/{id}= (its realms' names, joined: "Area 52, Ner'zhul"), and one =commodities= venue ("US commodities"), whose attributes say ="commodities": true= and ="region_wide": true= -- one market every realm trades on, which crafting buys reagents from whatever realm is picked. All are =auction_house= venues in the region's group, so region medians compare realms of one region.
- *Instruments*: one per item, and one per variant of an item, in the =wow-item= namespace (the source's instrument namespace). A variant is filed under its plain item.
- *Listings*: one per auction, with its id, so the store can tell what sold between two snapshots. Each snapshot is complete -- an item that vanished is out of stock -- and dated by Blizzard's =Last-Modified=.
- *Names and details*, lazily: up to =item_names_per_fetch= items a fetch has not named yet are looked up at =/data/wow/item/{id}=, lowest id first; the name, a category =Item class/Subclass= and attributes (=vendor_sell= in copper, =quality=, =level=) are stored once known and kept after.

** Icons, quality colours and tooltips

Looking an item up also builds how VENTURE draws it (=attrs.display=): its name in its quality's colour (grey, white, green, blue, purple, orange...), its icon, and its tooltip from the item endpoint's =preview_item= in the game's order -- item level, binding, unique, slot and type, damage and speed, armor, stats in their colours, /Use:/ and /Equip:/ effects in green, durability, requirements, the flavour text, the sell price. Pages draw the icon and colour beside the name and show the tooltip on hover.

Icons are fetched once. The media endpoint names an icon's file (=/data/wow/media/item/ID=, one request against the budget); the plugin downloads it from Blizzard's CDN only if its cache (=<state_dir>/plugin-cache/blizzard-auctions/icons/<file id>.jpg=, see [[file:../plugins.org][Plugins]]) does not have it -- an icon shared by many items is one file -- and serves it at =/blizzard/icons/<file id>.jpg= with =Cache-Control: max-age=31536000, immutable=, so browsers never reach Blizzard and do not ask again. Add =https://render.worldofwarcraft.com= to =feeds.allowed_origins= for the download. Items named by an earlier build are looked up again, at =item_names_per_fetch= a fetch, to get theirs.

** Links to Wowhead and Undermine Exchange

Each item's attributes carry =links= -- its Wowhead page, =https://www.wowhead.com/item=ID=, with a variant's bonus ids as =?bonus=1472:6646= (Wowhead shows that variant's item level and stats), or =/battle-pet/SPECIES= for a caged pet -- and =undermine_item=, the item as Undermine Exchange names it (the id, or =82800-SPECIES= for a pet). Each realm's venue carries its first realm's =slug= and a link template, =https://undermine.exchange/#us-SLUG/{undermine_item}=; the commodity market's uses any realm of the region, since commodities are region-wide. The instrument page shows them as /View on Wowhead/ and /View on Undermine Exchange/, and the venue table links each realm. They appear on an item as the source next fetches it, and on a realm once its name has been looked up in this process.

** The instrument key

#+begin_example
<item id>[:b<bonus>,<bonus>...][:m<type>=<value>,...][:p<species>[.<breed>]]

2770                              Copper Ore
19019:b1472,6646:m9=70,28=2       one variant of an item: two bonuses, two modifiers
82800:p39.5                       a caged battle pet: species 39, breed 5
#+end_example

Bonus ids are sorted ascending with repeats dropped, modifiers sorted by type then value: the API lists both in no meaningful order, and two spellings of one variant would split its history. Some modifiers (the player level an item dropped at) split goods a buyer thinks of as one; list the types that matter in =key_modifier_types= to drop the rest. A pet's level and quality are left out of its key.

** The price

In copper, the auction's =unit_price= when it has one (commodities, and stackables on a realm); otherwise its =buyout= divided by its quantity, rounded half to even. An auction with a bid and no buyout is *skipped*, and the run notes how many (=N bid-only auctions skipped=): it cannot be bought now, so its bid is no price to buy at -- listed, it became the realm's cheapest and Deals, Browse and the arbitrage scan sent buyers to it -- and its end, whether a bid won it or it expired, would read as a buyout sale. With =include_bid_only= on, it is listed at its current =bid= divided by its quantity instead, and the run says how many were. An auction with no item, no quantity or no price is refused and counted.

** time_left, and what counts as sold

Blizzard gives each auction a bucket, and the store keeps the *least* time the auction still has, in seconds:

| =time_left= | Means           | Stored |
|-------------+-----------------+--------|
| =SHORT=     | under 30 min    | 0      |
| =MEDIUM=    | 30 min to 2 h   | 1800   |
| =LONG=      | 2 to 12 h       | 7200   |
| =VERY_LONG= | 12 to 48 h      | 43200  |

The lower bound, because the store's sale estimate asks whether an auction that vanished between two hourly snapshots *could* have expired: a LONG auction gone within the hour cannot have, so it sold (or was cancelled -- the estimate's known bias); a SHORT one may have, so it counts as expired. The upper bound would count every expiry as a sale and inflate every sale rate the arbitrage scan reads.

* Recipes

The =import_recipes= action reads the professions into =recipe= and =recipe_component= records, for crafting and for the arbitrage =transform= strategy. One command imports a crafter's own professions, this expansion only:

#+begin_src sh
venturectl act data_source 3 import_recipes professions="Alchemy, Inscription" skill_tier="Khaz Algar" \
    max_recipes=500 create_products=true venture_id=2
# Read 412 recipes: 371 created, 0 updated, 0 unchanged, 41 skipped. ... Done: every recipe has been read.
#+end_src

=professions= names them by name (any case) or Blizzard's id, comma separated; =skill_tier= keeps the skill tiers whose name has it in it ("Khaz Algar" is "Khaz Algar Alchemy", "Khaz Algar Inscription"), so the older expansions are never fetched; =max_recipes= at its most (500) covers a profession's expansion in one call. Should the answer end "More remain: run again with cursor=...", run the same command with that =cursor== added until it says "Done". Running it again later picks up new recipes and changed quantities and changes nothing else.

| Parameter         | Meaning                                                                                          |
|-------------------+--------------------------------------------------------------------------------------------------|
| =max_recipes=     | recipes this call reads, 1 to 500; 50 by default                                                 |
| =professions=     | only these professions, by name or id, comma separated: "Alchemy, Inscription" or "171,773"      |
| =skill_tier=      | only the skill tiers (expansions) whose name contains this, case folded: "Khaz Algar"            |
| =profession_id=   | only this profession (Blizzard's id: 164 Blacksmithing, 186 Mining...)                           |
| =cursor=          | what the last call said to continue with                                                         |
| =create_products= | make a product for an item that has none                                                         |
| =venture_id=      | the venture new products and recipes belong to; required with =create_products=                  |
| =recipes=         | the recipes themselves, at most 2000, instead of Battle.net's tree (below)                       |

Each recipe is filed under =recipe= categories that follow the professions' book -- /Alchemy / Khaz Algar Alchemy / Potions/; a tier named only for its profession (/Mining/ under Mining) is left out -- so Crafting filters by a profession, an expansion or one section of it. A recipe imported before recipes were filed gets its place the next time the import reads it; one a person refiled keeps theirs.

Each item a recipe names becomes an =instrument= record under the source (promoted from the store when the auctions have seen it, made outright when not), and the recipe points at that instrument's product. Without =create_products=, a recipe whose items have no product is skipped and the result names the item -- link its instrument to a product, or run again with it. A recipe that makes no item (an enchant) is skipped. Two slots of one reagent become one line; a proc's range (=crafted_quantity= minimum and maximum) is read as its minimum. Running it again changes nothing it made: a recipe is found by its output product and name, a line by its recipe and product, and only a quantity that moved (or a recipe not yet filed) is written; a line someone added by hand is left alone.

It runs on the main thread -- it writes records -- and blocks for the requests it makes, one per recipe, each within =feeds.request_timeout=, which is what =max_recipes= bounds. It needs an editor.

** The recipes your characters know, from TradeSkillMaster

Battle.net's tree is every recipe there is; what a crafter wants priced is the ones their characters know. TradeSkillMaster already has that list -- per craft its spell, name, profession, the item and how many it makes, the reagents, and who knows it -- and =tsmctl venture recipes= sends it to the same action as =recipes=, a JSON array. With =recipes= nothing of Battle.net is read (no token, no index, no recipe; Battle.net's recipe ids are not TSM's spell ids anyway), and =max_recipes=, =profession_id=, =professions=, =skill_tier= and =cursor= are refused rather than ignored (an empty one, as a form posts it, is no value). The call is

#+begin_example
POST /api/v1/data_source/3/actions/import_recipes
{"create_products": true, "venture_id": 2, "recipes": [
  {"spell_id": 56029, "name": "Spellweave Gloves", "profession": "Tailoring", "expansion": "Northrend", "category": "Gloves",
   "item": 42113, "quantity": 1,
   "reagents": [{"item": 41511, "quantity": 4}, {"item": 41593, "quantity": 1}],
   "known_by": ["Havemércy-Thorium Brotherhood"]}]}
#+end_example

and the answer is the data source, its =result= the same sentence the walk writes:

#+begin_example
Read 1285 recipes: 1201 created, 0 updated, 0 unchanged, 84 skipped. Skipped: recipes[17] (spell 2963): reagents must be a list of 1 to 32 reagents. ... Done: every recipe supplied has been read.
#+end_example

| Member       | Required | Meaning                                                                                                   |
|--------------+----------+-----------------------------------------------------------------------------------------------------------|
| =spell_id=   | yes      | a positive whole number; the recipe's identity, kept as its =external_ref= =wow-spell:<id>=               |
| =name=       | yes      | the recipe's name                                                                                         |
| =profession= | yes      | the profession, its top =recipe= category                                                                 |
| =expansion=  | no       | text or null: the profession's tier as the game labels it less the profession's word ("Khaz Algar"; the bare tier "Classic"), the category under the profession |
| =category=   | no       | text or null: the section of the profession's book, the category under the expansion (or the profession) |
| =item=       | yes      | the item id it makes -- an instrument key in the source's namespace (=wow-item=), as the store keys items |
| =item_name=  | no       | what to call the item's instrument and product when the store has never seen it (else its id)            |
| =quantity=   | no       | how many a craft makes, a number of at least 1, 1 when left out; a fraction (a proc's 1.5) is rounded down |
| =reagents=   | yes      | 1 to 32 of ={"item": id, "quantity": whole number >= 1}=, each with an optional =name= like =item_name=   |
| =known_by=   | no       | the characters that know it, at most 100, as market data account keys -- the =key= of the character's =account= push line, ="<Name>-<Realm>"= -- kept exactly, sorted and once each in the recipe's =known_by= field (Crafting filters on it), replaced whole by every import that says it, and on a =Known by:= line of its notes |

A call takes at most 2000 recipes; more is refused whole, and so is a value that is not an array (a JSON string holding the array is read the same, which is what the action's form and =venturectl act data_source 3 import_recipes recipes="$(cat recipes.json)" create_products=true venture_id=2= send). An element of the wrong shape is skipped and named by its place (=recipes[17]=) in the result, which lists the first ten reasons; the others are made. Every element is a transaction of its own and the call blocks the server while it runs, so send a large list in parts of a few hundred.

What it writes is what the walk writes -- instruments promoted or made, products with =create_products=, the "has no product" skip without it, one line per reagent -- with three differences:

- *Found by its spell.* A recipe is found again by =external_ref= =wow-spell:<id>= (deleted ones included: a recipe a person deleted is skipped and says so), else by what it makes and its name when that recipe has no reference yet -- so a recipe the Battle.net walk made first is adopted, not doubled. The spell decides what it makes: a changed =item= or =quantity= is written.
- *The list is the whole recipe.* A reagent's changed quantity is written, and a line whose product the list no longer names is deleted; a reusable line (a tool a person added) stays.
- *Filed under profession / expansion / section*, a level not given left out; the profession is the same top category the walk files under, so one Crafting filter covers both (the walk's tier is Blizzard's name, "Khaz Algar Tailoring", where TSM's label is "Khaz Algar"). A recipe a person refiled keeps its place.

=known_by= is the recipe's =known_by= field and a line of its notes: both replaced when the characters change (a character who no longer knows it drops off), left alone when the member is left out, emptied by an empty list; every other line of the notes is a person's and is kept. A second call with the same list -- its characters in any order -- changes nothing.

* Fees: =wow_auction=

Give each realm's =venue= record the fee model, so a scan -- and Crafting, and the flip planner -- nets the auction house's cut and deposit out of every flip and craft. One command does every venue the source's store knows, the commodity market included:

#+begin_src sh
venturectl act data_source 3 set_venue_fees
# 85 venues given wow_auction (cut_percent: 5 duration_hours: 48), 0 kept the fee model they already had.
#+end_src

=set_venue_fees= promotes each venue to a record (idempotent) and gives every one that names no fee model =wow_auction= with =cut_percent= (5 by default), =duration_hours= (48) and, when given, =deposit_factor_percent=; =replace=true= also replaces a model a venue already names. Run it again after the realm list grows. One venue by hand:

#+begin_src sh
venturectl market promote 3 venue 3676
venturectl update venue 12 fee_model=wow_auction "fee_params=cut_percent: 5
duration_hours: 48"
#+end_src

A venue with no fee model charges nothing in a scan; Crafting names each one it sells at, beside the craft and in a note.

| Parameter                | Default | Meaning                                                                                      |
|--------------------------+---------+----------------------------------------------------------------------------------------------|
| =cut_percent=            | 5       | the auction house's share of a sale                                                          |
| =duration_hours=         | 48      | 12, 24 or 48: the listing's duration, which sets the deposit share                           |
| =deposit_factor_percent= | by duration | the deposit as a percent of the vendor price, replacing the classic shares               |

The deposit is the classic formula, 15% of the item's vendor price per 12 hours (15%, 30%, 60%), times the units, refunded when the auction sells and lost when it expires -- which the scan's listing loss counts against the sale rate. Retail has charged commodities differently since Dragonflight; set =deposit_factor_percent= to what your realms charge. The vendor price is the instrument's =vendor_sell= attribute; an item the source has not looked up yet is quoted with no deposit rather than a guessed one. The sale must be in a currency with exponent 4. Buying is free.

* Browsing, scanning, exporting

Once a sync has run: =/market/browse= lists every item at every realm with its price against the region median; =/market/i/SOURCE/2770= is one item's history, heat map and other realms; =/market/deals= and =/market/venues= work as for any source (see [[file:../market-data.org][Market data]]). On =/arbitrage=, the =spread= tab finds cross-realm flips net of =wow_auction= fees, =transform= prices imported recipes from the cheapest realm, and =Export= offers *TSM group import*:

#+begin_example
i:2770,i:2589,i:19019,p:39
#+end_example

one TradeSkillMaster item string per item a row names -- the row's item and a craft's reagents -- each once, a variant as its item, a pet as =p:<species>=; paste it into TSM's group import.

=/arbitrage/crafting= is every imported recipe at once: pick a profession or expansion, the realm you buy reagents on (commodities always come from the region's market) and the realm you sell on, and every recipe shows its reagent cost, what it sells for, the cut, the deposit, the profit and the margin, sortable, with each price's age. "Add to plan" there, on Deals and on =/arbitrage= puts a craft or a flip on =/arbitrage/plan=, the flip planner: what to buy on each realm and the most to pay, what to post on each and at what price, the gold it needs and what it should bring back, exported as CSV or as a TSM group of what to buy (=/arbitrage/plan/export?format=tsm=). See [[file:../arbitrage.org::*Crafting][Arbitrage: Crafting]] and [[file:../arbitrage.org::*The flip planner][the flip planner]]. =venturectl report arbitrage_scan strategy=spread data_source_id=3= (or =venturectl arbitrage scan spread data_source_id=3=) gives the same rows on the command line. [[file:arbitrage-wow-cross-realm.org][The cross-realm flip worked example]] takes one of those rows to a closed trade, and [[file:arbitrage-crafting.org][the crafting example]] does the same for a recipe; [[file:../arbitrage.org][Arbitrage]] has every strategy, option and fee model.

* When it goes wrong

| The run says                                              | Do                                                                                     |
|-----------------------------------------------------------+----------------------------------------------------------------------------------------|
| =... must be a registered currency with exponent 4=        | register GOLD (above), or name another in =currency=                                    |
| =Battle.net needs a client=                               | set =client_id= in the settings and =client_secret= on the credentials page             |
| =Battle.net refused the client credentials (HTTP 401)=     | the id and secret do not match; rotate the secret on the credentials page              |
| =https://us.api.blizzard.com is not one of feeds.allowed_origins= | add the region's API origin and =https://oauth.battle.net=                    |
| =... answered 429 Too Many Requests; retry after N seconds= | nothing: the unit waits; lower the realms or the budget if it recurs                  |
| =Battle.net has no connected realm 1234 (HTTP 404)=        | the id is wrong for the region; the index at =/data/wow/connected-realm/index= lists them |
| =item names: N items still to name=                        | nothing: later fetches name them, =item_names_per_fetch= at a time                      |
| =realm-index: The connected realm index lists 0 realms=, or an HTTP error | nothing: the last known realm list keeps serving, and the unit tries again        |
