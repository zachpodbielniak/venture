* Zero to running

This page is one path, in order: get the prerequisites, build, start an
instance seeded with the demo organisation, open the five-card home,
issue an invoice, import a bank statement that pays it, close a period,
stop. Every block is copy-pasteable from a checkout, and every block
after the build is run by the test suite exactly as printed here, against
SQLite, with its result asserted (=tests/docs-quickstart.sh=, driven by
=test-docs=). If a command is on this page, it works; if it stops
working, the suite goes red before you find out.

The build is the slow part: a fresh tree compiles nine vendored
libraries as well as VENTURE, which takes several minutes on four cores.
Everything after it takes under a minute.

* 1. Prerequisites

On Fedora, =make list-deps= prints the packages the build needs; two more
are podomation's and easy to miss:

#+begin_src sh
sudo dnf install -y git gcc make $(make list-deps | tail -n +2) libetpan-devel libgudev-devel
#+end_src

You also need =curl= and =python3=, which the demo seeding uses to talk
to the API. Emacs is optional: it is what renders the documentation
site when present, and the builtin renderer does the job when it is not
(see [[file:docs-site.org][the documentation site]]).

* 2. Build

** Native, from the tree

#+name: build-native
#+begin_src sh
git submodule update --init --recursive
make DEBUG=1
#+end_src

Output lands in =build/debug/=: the =venture= server, the =venturectl=
client, the example plugins and the pod modules. A release build
(=make=) lands in =build/release/= and the rest of this page works the
same with =BUILD_TYPE=release=.

** Or a container

If you would rather not install a toolchain, the container builds
everything inside the image and gives you an empty instance on
127.0.0.1:8747 with the owner password in its log:

#+begin_src sh
git submodule update --init --recursive
podman-compose up --build -d
podman logs venture-dev | grep -A3 'owner account'
#+end_src

The container path stops here: the demo organisation below is seeded by
a script that drives the binaries in =build/=, so it is a build-tree
feature. Follow [[file:containers.org][Containers]] for the rest of a
containerised install, and come back to step 5 with an API token from
=/account/tokens= once you have data of your own.

* 3. First run, with the demo organisation

Two variables for the rest of the page. The defaults are what a person
wants; the test suite overrides both so its run is private.

#+name: qs-env
#+begin_src sh
export VENTURE_SERVER="http://127.0.0.1:${PORT:-8749}"
export VENTURE_DEMO_STATE="${VENTURE_DEMO_STATE:-$PWD/build/demo}"
export PATH="$PWD/build/${BUILD_TYPE:-debug}:$PATH"
#+end_src

Then start a throwaway instance and seed it. This is the same thing
=make DEBUG=1 DEMOFLAGS=-d demo= does after building; the script takes
=--help=.

#+name: qs-seed
#+begin_src sh
tools/venture-demo.sh --detach
export VENTURE_TOKEN="$(cat "$VENTURE_DEMO_STATE/token")"
venturectl health
#+end_src

It prints the URL and the owner password when it is ready, and leaves an
owner API token in =$VENTURE_DEMO_STATE/token= so the CLI works at once:

#+begin_src
  Created the owner account.
  Username: owner
  Password: ffda5449ded6106ab817d6ec

  This is shown once. Save it now.

VENTURE 0.6.0 listening on http://127.0.0.1:8749
#+end_src

What is in there: two ventures, a year of sales and expenses posted
through to a general ledger, companies and contacts, a sales pipeline,
invoices issued and one settled, supplier bills, a matched bank
statement, a fiscal year with its first quarter closed, a support desk,
a sprint, a release and an incident, and two dashboards. Every record
went in through =venturectl= and the REST API, so the script itself
(=tools/venture-demo.sh=) is the shortest description of what a working
VENTURE looks like.

It listens on 8749, not 8747 or 8748, so it cannot collide with a
container or with =just start=, and it refuses to start if something
else answers there. Its database is =$VENTURE_DEMO_STATE/venture.db=
and is deleted and rebuilt on every run.

* 4. Open the five-card home

Open =$VENTURE_SERVER= in a browser and sign in as =owner= with the
password the script printed. The home page is the headline cards, one per
question the business is run on: P&L, CAC, churn, LTV:CAC and support
(and recurring revenue when billing is on), each a number for this month,
an arrow against last month, and a link to the report it came from. The
same cards are one JSON call, an array with one object per card:

#+name: qs-home
#+begin_src sh
curl -s -H "Authorization: Bearer $VENTURE_TOKEN" \
  "$VENTURE_SERVER/api/v1/headline?period=this_month" \
  | python3 -c 'import json, sys
for card in json.load(sys.stdin):
    print(card["key"].ljust(10), card["label"].ljust(28), card["value"])'
#+end_src

See [[file:dashboards.org][Dashboards]] for what each card reads and how
to put a dashboard of your own in its place.

* 5. Issue an invoice

An invoice is a record with lines; issuing it is a state change the
settlement service owns, which is why =status=sent= goes through
=update= and not a hand-written flag. Bill the first company in the
demo for 250 USD, dated today:

#+name: qs-invoice
#+begin_src sh
# Every date below is a calendar date in the *business* timezone
# (=locale.timezone=), which the server reports. Do not substitute the UTC
# date: west of UTC it is already tomorrow's business date for part of
# every evening, and a financial event may not be dated ahead of today.
ZONE="$(curl -sf -H "Authorization: Bearer $VENTURE_TOKEN" \
  "$VENTURE_SERVER/api/v1/settings" \
  | python3 -c 'import json, sys; print(next(s["value"] for s in json.load(sys.stdin) if s["name"] == "locale-timezone"))')"
CUSTOMER="$(venturectl -f json list company limit=1 \
  | python3 -c 'import json, sys; print(json.load(sys.stdin)["records"][0]["id"])')"
INVOICE="$(venturectl -f json create invoice number=QS-1 status=draft \
  company_id="$CUSTOMER" issued_at="$(TZ="$ZONE" date +%F)" \
  due_at="$(TZ="$ZONE" date -d '+30 days' +%F)" terms='30 days' \
  | python3 -c 'import json, sys; print(json.load(sys.stdin)["id"])')"
venturectl create invoice_line invoice_id="$INVOICE" \
  description='Onboarding workshop' quantity=1 unit_price=250.00 position=1
venturectl update invoice "$INVOICE" status=sent
venturectl get invoice "$INVOICE"
#+end_src

The invoice is now =sent=, one line of 250.00 USD, nothing paid against
it yet; =/e/invoice/$INVOICE= shows it with its lines and a printable
view. See
[[file:receivables.org][Customer receivables]] for receipts, credits and
refunds.

* 6. Import a bank statement

The bank says the customer paid. A statement is imported, never typed:
the file below is one CSV line wrapped in the import's JSON, against the
demo's current account. Then the receipt is created from the bank line
and allocated to the invoice, which settles it.

#+name: qs-bank
#+begin_src sh
BANK="$(venturectl -f json list bank_account limit=1 \
  | python3 -c 'import json, sys; print(json.load(sys.stdin)["records"][0]["id"])')"
TODAY="$(TZ="$ZONE" date +%F)"
python3 - "$TODAY" > "$VENTURE_DEMO_STATE/statement.json" <<'EOF'
import json, sys
today = sys.argv[1]
print(json.dumps({
    "format": "csv",
    "data": "Date,Amount,Description,Reference,FitID\n"
            f"{today},250.00,ONBOARDING WORKSHOP,QS-1,QS-FIT-1",
    "period_start": today, "period_end": today,
    "opening_balance": "1000.00", "closing_balance": "1250.00"}))
EOF
STATEMENT="$(venturectl -f json bank import "$BANK" @"$VENTURE_DEMO_STATE/statement.json" \
  | python3 -c 'import json, sys; print(json.load(sys.stdin)["id"])')"
LINE="$(venturectl -f json list bank_transaction statement_id__eq="$STATEMENT" \
  | python3 -c 'import json, sys; print(json.load(sys.stdin)["records"][0]["id"])')"
venturectl bank create "$LINE" "{\"type\":\"receipt\",\"customer_id\":$CUSTOMER}"
RECEIPT="$(venturectl -f json list payment customer_id__eq="$CUSTOMER" \
  | python3 -c 'import json, sys; print(max(r["id"] for r in json.load(sys.stdin)["records"]))')"
venturectl create payment_allocation payment_id="$RECEIPT" invoice_id="$INVOICE" \
  date="$TODAY" amount=250.00
venturectl get invoice "$INVOICE"
#+end_src

The bank line is =matched= to the receipt it created, and the invoice is
=paid=, because a receipt was allocated to it rather than because
anybody said so. =/banking= shows the statement and what is still open.
See [[file:banking.org][Banking]] for automatic matching, rules and
reconciliation.

* 7. Close a period

The demo's fiscal year has its first quarter closed. Close the next open
period: the close checks refuse unbalanced batches and draft invoices
dated inside it, snapshot every report as it stood, and refuse any later
posting dated into it.

#+name: qs-close
#+begin_src sh
PERIOD="$(venturectl -f json list fiscal_period state__eq=open \
  | python3 -c 'import json, sys
rows = sorted(json.load(sys.stdin)["records"], key=lambda r: r["start_at"])
print(rows[0]["id"])')"
venturectl update fiscal_period "$PERIOD" state=closed
venturectl get fiscal_period "$PERIOD"
#+end_src

The period is =closed= with =closed_by= and =closed_at= stamped by the
service. See [[file:periods.org][Fiscal periods]] for reopening,
locking, and reports as of a close.

* 8. Stop

#+name: qs-stop
#+begin_src sh
tools/venture-demo.sh --stop
#+end_src

That stops the instance and deletes =$VENTURE_DEMO_STATE=. Run step 3
again for a fresh one; nothing you did to the demo matters.

* Where next

- The documentation you are reading is served by every running instance
  at =/docs=, and =make docs-site= renders it into =build/docs-site=. See
  [[file:docs-site.org][The documentation site]].
- A local instance that keeps its data between restarts: =just start=,
  on 127.0.0.1:8748, with =just sql= to read the database while it runs.
  =just= on its own lists the recipes.
- A real first run of your own: =./build/debug/venture --state-dir
  ~/.local/share/venture= creates the schema, seeds a chart of accounts
  and prints the owner password once. Open =/setup= to finish the legal
  entity's books before the first invoice --- see
  [[file:setup.org][Accounting setup]] --- and mint a token at
  =/account/tokens= for =venturectl=.
- Record your own trade with =venturectl create venture=, =product=,
  =sale= and =expense=, then =venturectl report pnl this_month=;
  =venturectl types expense= lists every field of a record type. See
  [[file:cli.org][venturectl]].
- Run it as a service: a user unit with =ExecStart=%h/.local/bin/venture
  --state-dir %h/.local/share/venture= and a persistent
  =VENTURE_SESSION_SECRET=, or sessions end at every restart. See
  [[file:configuration.org][Configuration]].
- The tests: =make DEBUG=1 test=, =make DEBUG=1 test-one T=test-docs=.
  See [[file:testing.org][Testing]].
