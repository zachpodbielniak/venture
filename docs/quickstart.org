* Seeing it with data in it

An empty ERP tells you nothing about what it is for. =make demo= builds the debug binaries, starts a throwaway instance on 127.0.0.1:8749 and seeds a small but complete business into it:

#+begin_src bash
make demo               # build, seed, run in the foreground; Ctrl+C stops it
make DEMOFLAGS=-d demo  # leave it running in the background
make demo-stop          # stop that one and delete its data
#+end_src

It prints the URL and the owner password when it is ready. What is in there: two ventures, a year of sales and expenses, companies and contacts and a pipeline, two invoices with one overdue, a support desk with service-level policies, macros, a rota, a sprint, fourteen tickets with a conversation and logged time and one deliberately missed promise, a release that went out and the incident that followed, and two dashboards — one for the desk, one for the money. Every report has figures.

Three things worth knowing about it. It listens on *8749*, not 8747 or 8748, so it cannot collide with a container or with =just start=; it refuses to start if something else is already answering there, because seeding example data into a real instance is the one mistake it must never make. The database is =build/demo/venture.db= and is *deleted and rebuilt on every run*, so nothing you do to the demo matters. And every record goes in through =venturectl= and the REST API rather than into the database directly, so a demo that seeds is also a demonstration that the API can build one.

The script is =tools/venture-demo.sh= and takes =--help=. Everything it creates is readable there: it is the shortest description of what a working VENTURE looks like.

* Running a local instance

There is a =Justfile= for this, because it is a workflow rather than a build:

#+begin_src bash
just start          # build if needed, then run on 127.0.0.1:8748
just status         # is it up
just password       # the owner password, from the first-run log
just ctl list ticket
just sql "SELECT id, title FROM tickets"
just logs           # follow
just restart
just stop
just reset          # throw the database away -- asks twice
#+end_src

Run =just= on its own for the grouped list.

Port 8748, not the configured default of 8747: that is where a containerised instance from =compose.yaml= listens, and colliding with it would mean either failing to bind or — worse — talking to the container while you believe you are testing the build tree.

The session secret is generated once into the state directory rather than at each startup, so a restart does not log you out. =just reset= removes it along with the database, since both belong to the instance being discarded.

=just reset= is the only recipe that destroys anything, so it asks twice and prints what is actually there first — "delete 47 tickets and 12 invoices?" gets read, where "delete the database?" gets answered by reflex. With no terminal to ask it refuses rather than assuming, which is what stops a pipeline eating a local database. =just force=true reset= skips both prompts for a script that means it.

=just sql= is the reason to prefer this over =make compose-up=: when a report is wrong, opening the database with the same tools you would use on any other file is the first useful thing, and it works while the server is still running.

make still builds. The Justfile only ever calls it.
* Quickstart

** Build

#+begin_src sh
git submodule update --init --recursive
make DEBUG=1
#+end_src

Output lands in =build/debug/=. A release build (=make=) lands in =build/release/=.

On Fedora, =make list-deps= prints the packages to layer into an image build:

#+begin_src
gcc make pkgconf-pkg-config glib2-devel libyaml-devel json-glib-devel
libsoup3-devel libxml2-devel sqlite-devel libpq-devel readline-devel
gobject-introspection-devel
#+end_src

** First run

#+begin_src sh
./build/debug/venture --state-dir ~/.local/share/venture
#+end_src

On a fresh database this creates the schema, seeds a default organisation, a chart of accounts and a set of tax categories, then prints an owner password once:

#+begin_src
  Created the owner account.
  Username: owner
  Password: ffda5449ded6106ab817d6ec

  This is shown once. Save it now.

VENTURE 0.6.0 listening on http://127.0.0.1:8747
#+end_src

Pass =--owner-password= to choose it yourself.

** Mint a token for the CLI

In the browser: *Your account → API tokens*, or
[[http://localhost:8747/account/tokens][localhost:8747/account/tokens]].
Name it, optionally give it an expiry, and copy the secret — it is shown
exactly once. The same page revokes it again.

Over HTTP, if you would rather not leave the terminal:

#+begin_src sh
# Sign in and keep the session cookie
COOKIE=$(curl -s -i -X POST -d 'username=owner&password=YOURPASSWORD' \
  localhost:8747/login | grep -oP 'Set-Cookie: \K[^;]+')

# Mint a token; it is shown exactly once
curl -s -X POST -H "Cookie: $COOKIE" -H 'Content-Type: application/json' \
  -d '{"name":"laptop"}' localhost:8747/api/v1/tokens
#+end_src

#+begin_src sh
export VENTURE_TOKEN=vk_...
export VENTURE_SERVER=http://127.0.0.1:8747
#+end_src

Put those in =~/.bashrc-secrets= rather than =~/.bashrc=.

** Record something

#+begin_src sh
venturectl create venture name='Book imprint' slug=books \
                          venture_type=books status=active

venturectl create product venture_id=1 name='Starfall' \
                          genre=science-fiction list_price=14.99

venturectl create sale venture_id=1 product_id=1 quantity=1 \
                       gross=14.99 fees=2.10 occurred_at=2026-08-14

venturectl create expense venture_id=1 description='Cover art' \
                          amount=250.00 category=supplies \
                          deductibility=full occurred_at=2026-08-01
#+end_src

** Look at it

#+begin_src sh
venturectl report pnl this_month
venturectl report categories this_year     # by genre
venturectl list sale period=this_month
venturectl types expense                   # every field of a record type
#+end_src

Or open http://127.0.0.1:8747 in a browser. Worth knowing there:

- =Ctrl+K= focuses the search box in the sidebar; =/search= sweeps every
  record type at once, honouring each type's searchable fields and the
  active entity's scope.
- Every list paginates, sorts by clicking a column header (again to
  reverse), and exports the current view — same search, same sort — as CSV
  via the Export button.
- The dashboard shows open tickets by status, the weighted deal pipeline,
  and the latest audit-trail activity alongside the report cards.
- Every list has Import as well as Export: CSV in, all-or-nothing, with the
  Template button giving the exact headers.
- =/e/invoice= is invoicing: lines with exact money arithmetic, a printable
  view, and marking paid records the sale automatically.
- =/automations= edits the automation rules with live parser diagnostics;
  =/plugins= configures loaded plugins, and plugins follow the changes
  without a restart.
- The AI panel takes attachments and screenshots — paste an ad dashboard
  and it stages the campaign for approval.
- =?= shows the keyboard shortcuts.

** Ask about it

With an API key in the environment for your provider, the *Ask VENTURE*
launcher at the bottom right of every page opens the AI panel (=Ctrl+/=). It
answers questions and drafts changes; changes are staged for approval, not
applied. Conversations are stored server-side, so the panel resumes where
you left off — even in a different browser — and the ☰ button lists earlier
ones:

#+begin_src sh
export ANTHROPIC_API_KEY=sk-...
./build/debug/venture --state-dir ~/.local/share/venture
#+end_src

** Run it as a service

#+begin_src sh
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/venture.service <<'EOF'
[Unit]
Description=VENTURE
After=network.target

[Service]
ExecStart=%h/.local/bin/venture --state-dir %h/.local/share/venture
Environment=VENTURE_SESSION_SECRET=CHANGE-ME
Restart=on-failure

[Install]
WantedBy=default.target
EOF

systemctl --user enable --now venture
#+end_src

Set =VENTURE_SESSION_SECRET= to something persistent, or sessions end at every restart.
