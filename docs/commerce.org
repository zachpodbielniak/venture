#+title: Commerce connectors
#+description: Import marketplace orders as invoices through document compose and settlement

* Commerce connectors

The =commerce= module is opt-in and requires =invoicing= and
=receivables=. Set =commerce.enabled: true=. Startup requires
=VENTURE_COMMERCE_SHOPIFY_TOKEN= (and optionally
=VENTURE_COMMERCE_SHOPIFY_SHOP=). Enabling without the token fails
configure/start and names the variable.

=VentureCommerceConnector= is a GInterface with a registry. A
Shopify-like connector turns orders into invoices through
=VentureDocumentService= compose and, when the order is paid, through
=VentureSettlementService=. There is no second ledger. The order id is
stored as =invoice.external-id= and is unique within the organization, so
a repeated import is a no-op. Line prices use the order currency
(never a silent USD default). Cancelled, voided and refunded orders
are skipped. The Shopify customer is matched or created as a company.

Tests register a fake connector and never open a network connection.

#+begin_src sh
venturectl commerce import
#+end_src

Automation:

#+begin_src text
pod shop_hour = cron->new("15 * * * *");
shop_hour->on_schedule => venture->commerce_import("1", "shopify");
#+end_src

The REST adapter requests complete ISO timestamps for both ends of the import
window and pages using =since_id= with at most 250 orders per response. It
refuses a non-progressing or over-limit pagination sequence before importing
anything. Authentication stays on URLs built from the configured shop; HTTP
redirects are refused. See the [[https://shopify.dev/docs/api/admin-rest/2025-10/resources/order][Shopify Order API]]
for the supported window and cursor parameters. The adapter currently pins
REST version =2025-10= and requires an existing app with order access.

The web importer uses the active organization; automation uses its explicit
organization argument. Both share the live connector registry, including
plugins, and use the same import transaction.

* Exact import boundary

Orders with taxes, discounts, tips, shipping lines, refunds or partial payments are refused before importing the batch because this adapter does not yet map those components to accounting entries. When the provider supplies =total_price=, the composed invoice must equal that total before any receipt is recorded; a mismatch rolls back the entire import, including newly created customers. Resolve unsupported orders through an explicit document and settlement workflow.
