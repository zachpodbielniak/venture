#+title: Transactional mail

* Delivery semantics

The =mail= module requires =core=. =mail_message= is a durable outbox and
=mail_template= stores organization templates. Both use the generated record
surfaces. A nonempty =idempotency_key= is unique within its organization,
including soft-deleted history. Enqueueing the same key returns the same row.

The delivery contract is "at-least-once submission, at-most-once automatic
retry, operator-resolved uncertainty". This does not promise duplicate-free
SMTP delivery. A successful send means relay acceptance, not inbox delivery.

A sweep commits =sending= with a lease before attempting submission. Between
the lease and the transport the outbox emits =before-send=; a source lane
that enqueued the message may recheck its eligibility there (an invoice paid
after its reminder was queued) and veto, which makes the row =cancelled= with
the handler's reason. A cancelled row spent no attempt and cannot be retried.
A definite failure before submission becomes =failed= with exponential backoff
(60 seconds, 120 seconds, and so on), then =dead= at the attempt limit.
A lost submission reply becomes =uncertain= and is never automatically
retried. An expired =sending= lease also becomes =uncertain=: a process crash
may have happened after the relay accepted the message. Deliberate retry
reuses the same row and Message-ID; receiving MTAs may deduplicate it.

* Enqueueing from another feature

=venture_mail_outbox_enqueue()= accepts an unsaved =VentureMailMessage= with
an exact organization, recipient, subject, text/HTML bodies and an
idempotency key. Call it inside the transaction that writes the source
record. It performs no network I/O. A delivery sweep must run after commit.

=VentureMailer= is a GInterface with synchronous and async send/finish
methods. =VentureLogMailer= records independent message snapshots in memory
and supports injected errors for tests. Ordinary tests send no external mail;
the opt-in relay fixture submits only to its disposable local container.

The =sequence_delivery=, =billing_notice=, =quote_delivery= and =collection_notice= adapters each
read one source row, construct the message, use a source-type/id-derived
idempotency key and call enqueue. The source lane owns eligibility and
content; the outbox owns submission. Those source-row adapters remain a
cross-lane integration function, not additional SMTP implementations.

A scheduled =report_pack= with =deliver=email= is one more such source: the
pack sweep enqueues the run's retained output with its JSON and CSV files
attached, keyed by pack and delivery clock, and records the outcome on the
pack. See [[file:reporting.org][Reporting]], Delivery.

Service-generated invitations use the sensitive =private_text_body= field for their bearer link. Only the outbox enqueue service may create this content; stored messages remain immutable. Public record serialization, forms and audit omit it. SMTP sends this private text in place of both public body alternatives, so an HTML mail client cannot hide the access link. Its HTML twin, the equally sensitive =private_html_body= (migration =000331_private_mail_html=), is used by senders that render an HTML template around the link, such as overdue reminders: when present it replaces the public HTML alternative, and a private text body without it still drops the public HTML. The same enqueue-only rule applies to both. The protected content remains in the database for durable retries and must be treated as a credential in database backups.

* Templates

Templates substitute ={field}= values from a record's public JSON fields
into subject, text and HTML. HTML values are escaped. Unknown and sensitive
fields are refused, and a template cannot render a different organization's
record. =venture_mail_template_render_values()= renders from an explicit
value set instead, for a message composed from several records; the caller
owns what enters it.

* SMTP configuration

The operator first enables =mail= and =integrations= and provides the
installation encryption key described in [[file:integrations.org][Organization integrations]].
The only installation-wide SMTP policy is the endpoint allowlist and,
optionally, an operator-owned CA bundle:

#+begin_src yaml
mail:
  allowed_endpoints: smtp.example.net:587,smtp.other.example:465
  tls_ca_file: ""                 # empty uses system trust
#+end_src

An empty allowlist refuses every organization SMTP endpoint. Entries match
an exact DNS hostname or IPv4 address and port; there are no wildcards.
The operator owns DNS/egress policy for those hosts. An organization cannot
supply a local CA/DKIM file, another transport's endpoint or an environment
variable reference. Passwords beginning =env:= are literal passwords.
Certificates are verified. =starttls= and =implicit= TLS are supported;
unencrypted SMTP is refused. The socket I/O timeout is at most 30 seconds,
and mail-glib retries are zero because the outbox owns retry decisions.

As an organization owner/admin, open *Mail settings* on its record, or
=/organizations/<id>/settings/mail=. Connect its host, port, authentication
method, username, password and sender. Optional sender name/reply address
and bounded timeout use the form's documented defaults. Credential fields
always render blank, including after errors. Rotation requires complete
settings and the exact displayed connection ID/version. Host, port,
authentication identity and sender identify an account; changing them
requires disconnect followed by connect. A stale form cannot overwrite a
replacement connection even if their numeric versions happen to match.

*Send test message* submits only its retained test message, using the
selected connection/version, and reports its outbox outcome. It does not
sweep other queued mail. Repeating the same form token reuses that test
message. Relay acceptance is =sent=; it is not proof of inbox delivery.
Disconnect keeps encrypted historical identity but stops further selection.
Credential rotation takes effect on the next preparation without restarting
or changing another organization. No credential cache is retained.

Production context mail selection never reads legacy =mail.host=,
=mail.username=, =mail.password_env= or another organization's account.
Migrate installation configuration by deliberately connecting each intended
organization; no default organization is inferred. The legacy C constructor
remains available only for explicitly injected adapters and existing socket
fixtures. Disabled =mail= makes the context mailer/outbox unavailable;
disabled =integrations= refuses production selection.

Before a transport worker starts, =VentureMailer.prepare= resolves settings
on the caller's repository thread. The concrete transport contains immutable
in-memory settings. The outbox commits =connection_id= and
=connection_version= before external I/O. A retry may use rotated credentials
for that same binding, but cannot move to a replacement account. A binding
or preparation refusal is a known pre-submission =dead= outcome; inspect it,
repair settings and deliberately retry, or enqueue a new message when a
previous account was replaced. An unattempted message selects its account
on its first attempt. Historical sent mail is not assigned an inferred
account on upgrade.

GMime and mail-glib compose and submit the message. SMTP errors retained on
the outbox are fixed, credential-free descriptions.

* Operator commands

#+begin_src sh
venturectl mail test to=operator@example.net
venturectl mail send to=customer@example.net subject='Your receipt' body='Thank you.'
venturectl mail send to=customer@example.net subject='Your invoice' --html invoice.html
venturectl mail deliver --limit 100
venturectl mail list state=uncertain
venturectl mail retry 42
#+end_src

Supply =organization_id=N= for a legal entity other than the default.
=mail test= performs one immediate submission through the configured mailer.
=mail send= only enqueues. A =failed= row has a scheduled retry; an
=uncertain= row needs a deliberate operator decision. Retry restarts its
attempt budget, retaining its Message-ID and audit history. Mail rows cannot
be deleted, restored or purged, preserving their idempotency keys.

The generated web list is =/e/mail_message?state=uncertain=. The invoice
page's Send button issues a draft through the settlement service and queues
its HTML invoice, together with a nonfinancial =invoice_event= of kind
=mail_queued=. Repeated Send presses return the same message. SMTP failure
does not unissue the accounting document. The organization's =invoice=
mail template supplies the subject and introductory text/HTML; the invoice
line table and total follow it. The default template is saved on first use.

User creation with an email queues a welcome notice. A subsequent password
hash change queues a password-reset notification, with both writes in one
transaction. No password is mailed. This uses the existing authenticated
password-change/reset workflow; it does not add a public reset-token flow.
Users without an email are skipped.

* Scheduling

Run a bounded sweep for each organization every minute. This podomation rule
uses the same outbox service as REST and the CLI, on the main thread:

#+begin_src text
pod mail_minute = cron->new("* * * * *");
mail_minute->on_schedule => venture->mail_deliver("1", "100");
#+end_src

The arguments are organization ID and attempt limit. Add a rule for each
organization. Use a scheduled rule, after business transactions commit.
Inbound mail has its own handler, =venture->mail_sync=; see Inbound,
Running it.

* Attachments and durable snapshots

=attachments= is a JSON field containing document references, for example
=[{"type":"document","id":42}]=, or inline content generated at enqueue time,
=[{"type":"inline","name":"pack.csv","mime":"text/csv","data":"<base64>"}]=,
which needs no document row and no attachment storage (a report pack's CSV
is one). Each document must exist, be live and
belong to the message's organization. Its file must be under the server's
=state-dir/attachments/= directory. At enqueue time the outbox copies the
bytes and metadata into its retained message attributes. Later file edits or
removal cannot change a retry. The combined attachment limit is 20 MiB.
GMime encodes the attachment bytes; Bcc addresses stay envelope-only.

* API

- =POST /api/v1/mail/send=: message fields; returns the queued row (202).
- =POST /api/v1/mail/test=: =to=; one immediate test submission.
- =POST /api/v1/mail/deliver=: =organization_id= and =limit= (1–1000).
- =POST /api/v1/mail_messages/:id/retry=: deliberate retry, optional organization.
- =POST /api/v1/invoices/:id/send=: atomic issue/enqueue/event, returns the message.
- =POST /api/v1/mail/sync=: the inbound sweep; =organization_id= and =limit= (1–1000 accounts).
- =POST /api/v1/mail_accounts/:id/sync=: one inbound account now, ignoring its backoff (owner).
- =POST /api/v1/mail_unmatched_senders/:id/create_contact= and =.../dismiss=.

Actions require editor access; generated lists require ordinary read access.
Mail actions refuse CLI =--stage=; use =--stage create mail_message= to stage
an enqueue through the generic record machinery. Delivery must run outside
any open database transaction, after all source writes commit.

* Upgrades and verification

The field tables add the mail tables and per-organization unique index.
The paired =000160_mail_outbox.sql= scripts verify that the uniqueness index
exists when its table exists, including upgrades with mail disabled. They do
not infer or send historical mail. Existing business rows are unchanged.

=test-mail= covers outbox states, retry exhaustion, retained keys, lease
expiry, template escaping, SMTP uncertainty and Message-ID/Bcc behavior over
a local socket, invoice/user consumers, atomic invoice/user rollback and attachment
snapshots. =test-mail-surfaces= exercises the real CLI against a private HTTP
server, action guards and the scheduled automation handler. =test-auth= covers
anonymous action refusals.

=VentureMailerRegistry= owns named transport implementations. The context uses
its =smtp= slot; =venture_context_set_mailer()= replaces it for tests or plugins.
Async completion returns on the initiating context. Selection may read the
database before launching a worker; transport workers never access it.

SMTP tests enforce organization write authority and policy-plugin vetoes before invoking the mail transport, just as an outbox enqueue does.

* Inbound

The =mail_sync= module requires =mail=, =crm= and =leads= and suggests
=capture=. It owns =mail_account=, =mail_inbound= and
=mail_unmatched_sender=. Accounts are assigned by organization administrators.
Credentials are encrypted, scoped to the saved account and organization, and
managed through [[file:connectors.org][connector settings]]. =mail_inbound= is written by the
sweep and refuses generic writes. =mail_unmatched_sender= stays ordinary CRM data.

** Accounts

An account names its mailbox address, explicit IMAP host and port, TLS or
STARTTLS security, login username, watched folders, optional capture address
and capture folder. =secret_env= is retained only as unused historical metadata;
no process environment password is resolved. Configure an explicit binding
before syncing. The operator must allow the exact host and port in
=imap.allowed_endpoints=. Production plaintext authentication is refused.

=private_owner_id= selects privacy at creation. Zero explicitly shares the
business mailbox with the organization. A positive active member ID creates
a private mailbox: its messages and raw documents belong to that member,
produce no CRM interactions, unmatched senders or capture items, and are
not published to organization notifications, automation, webhooks or knowledge
cross-references. Message-ID deduplication and threading are partitioned by
that ownership. Private ownership cannot later be changed or removed.


| Field                  | Meaning                                                                                      |
|------------------------+----------------------------------------------------------------------------------------------|
| =address=              | The mailbox the account receives as; never a contact match nor an unmatched sender            |
| =folders=              | Comma-separated folders; =INBOX= when empty. The capture folder is always added              |
| =capture_address=      | Exact capture address (see Capture); refused at save when the account's own mail would match |
| =capture_folder=       | Every message in it is a capture item                                                        |
| =ignore_patterns=      | Comma- or newline-separated globs (=noreply@*=, =*@notifications.example=)                   |
| =internal_domains=     | Comma-separated domains (subdomains included) that never become unmatched senders            |
| =sync_since=           | A folder's first sync starts at mail received on or after this date                          |
| =active=               | Included in the sweep; switched off after repeated refused logins                            |
| =consecutive_failures= | Syncs in a row that failed to reach the mailbox (service-owned)                               |
| =next_attempt_at=      | The sweep skips the account until then (service-owned)                                        |
| =last_synced_at=       | When the last sync finished, successfully or not                                             |
| =last_error=           | What stopped the last sync, and any folder or message that failed; empty when all was well   |
| =cursors=              | Per folder: =uid=, =uidvalidity=, and =failed_uid= / =attempts= for a failing message         |
| =sync_lease_until=     | Held while a sync runs (service-owned)                                                       |

The generated list shows the health columns first, so a failing mailbox is
visible at =/e/mail_account= without opening it.

** Syncing

=VentureMailSyncService= is the one service behind every surface. For each
watched folder it examines the folder read-only, compares its UIDVALIDITY
with the stored one, lists UIDs above the stored high-water mark, and
processes each message in its own transaction: the raw RFC 5322 bytes are
filed as a =document= of kind =email= under =state-dir/attachments/=, a
=mail_inbound= row records the folder, UID, UIDVALIDITY, Message-ID, thread
root and what was created, and the cursor advances. The UID key
(=v2:account:uidvalidity:uid:folder=) is unique within the organization,
including deleted rows, and is checked before the message is fetched, so a
rerun against the same mailbox creates and downloads nothing even if a
cursor write was lost. Rows filed before UIDVALIDITY was recorded carry the
older =account:folder:uid= key and a bare-number cursor; both are still read,
so an upgrade refetches nothing.

A document's =extracted_text= is the parsed body, never the raw MIME. Its
stored file name is a random token plus at most 96 bytes of the title, since
a subject is unbounded and a file name is not; the row keeps the whole
title. A file written for a message whose transaction rolls back is deleted.

*** Budgets, deadline and lease

The sweep runs on the main loop (see AGENTS.md: the only background thread
belongs to coding runs), so every call is bounded:

- A message budget, =message-budget= on the service (default 200). A sync
  or a sweep stops when it is spent and reports =deferred=; the cursors
  resume on the next call. A first sync of a large mailbox is therefore a
  series of calls, not one request that holds the server.
- A time budget, =time-budget= (default 45 seconds, under the CLI's HTTP
  timeout). The deadline re-arms every socket read with what is left, so a
  server that trickles a byte just inside a per-read timeout still ends on
  time. Running out while reading mail defers; running out before the
  session was established is a failure of the account.
- Per-message bounds, because both budgets are only consulted between
  messages and one message is filed in one transaction. A message keeps at
  most 100 recipients (past that it is treated as bulk, so nobody in it
  becomes an unmatched sender), the root and the latest 19 ids of its
  =References= header, and 25 attachments; a PDF is read up to 2000 pages
  or about 4 MiB of text. A deadline checked inside a message would not
  help: the message would roll back and overrun again on every sync.
- Per-command bytes: the IMAP client holds at most the command's largest
  literal plus 4 MiB, so a server cannot answer one command with thousands
  of message-sized literals.
- A lease: the sync stamps =sync_lease_until= before connecting and clears
  it when done. A second caller -- another process, or a request served from
  a nested main loop -- finds the lease and skips the account (=skipped= in
  the report) instead of filing the same UIDs twice.

*** Failures

What went wrong decides what happens next:

- *The session* (connection, TLS, a refused login, the time budget before
  the session was up): the sync stops, =consecutive_failures= increments and
  =next_attempt_at= backs off exponentially from 60 seconds to at most an
  hour. The sweep skips the account until then; =mail sync account_id=N= and
  the account's Sync now button ignore the backoff but not the lease. Five
  failures in a row ending in a refused login switch the account off and
  notify admins and owners, because a provider locks a mailbox that keeps
  presenting a wrong password. A successful sync resets the count. Errors
  name only an RFC 5530 response code from a fixed list (for example
  =[AUTHENTICATIONFAILED]=, =[UNAVAILABLE]=); server text never appears,
  because a rejected login line can carry the credential. =[UNAVAILABLE]= is
  treated as the wire, not the credentials.
- *A folder* the server refuses: recorded in =last_error=; the folders after
  it still sync, and nothing backs off.
- *A message*, for a reason that is its own (it will not parse, a save
  refuses it, the server returns no content, a constraint it breaks): the
  folder stops at that UID and its =attempts= count in the cursor. On the
  third failing sync the message is filed as a stub -- a =mail_inbound= row
  with =skip_reason=, no document and no CRM records -- and the folder moves
  on. List them with =/e/mail_inbound?skip_reason=...= or =venturectl list
  mail_inbound=.
- *Transient persistence* (a locked database, a record edited meanwhile,
  missing attachment storage): the sync stops and the same message is tried
  on the next call, spending no attempt.
- *An oversized message* (listed RFC822.SIZE over 20 MiB) is not refused:
  its header and the first 64 KiB of its text are fetched and filed at once,
  with =skip_reason= saying so. It reaches the timeline; a capture message
  that size creates no capture item, since its attachments are gone.

** Matching and threading

Every From, To and Cc address is normalised the way lead deduplication does
(=venture_lead_normalize_email()=: lower case, trimmed, +tag removed) and
compared with each contact's email; the contacts are indexed once per sync,
not queried per message. Each matched contact receives an =interaction= of
kind =email= carrying the contact's company (only when that company is not
deleted), the subject, the text body, the message date and =outbound= when
the message came from the account's own address. A contact with exactly one
open deal (not won or lost) gets that =deal_id=, unless an earlier message
in the same thread already names a deal, which wins. An address that matches
no contact but a lead records an interaction with =lead_id= instead.

The text body is the =text/plain= part, else the =text/html= part converted
to text (=venture_document_html_to_text()=, shared with the assistant's web
fetch), else the same from a forwarded message. Subjects, names and bodies
are made valid UTF-8, reading undeclared 8-bit text as windows-1252;
PostgreSQL refuses invalid UTF-8 outright.

Threads are resolved by In-Reply-To and References: a reply inherits the
=thread_id= of the earliest known ancestor, otherwise the oldest reference
or its own Message-ID becomes the root, so =/e/mail_inbound?thread_id=...=
lists a conversation. A message without a Message-ID gets
=<first 32 hex of its SHA-256>@venture.invalid=, stable across folders and
reruns.

The same Message-ID already filed -- under a second Gmail label, in another
account on the same thread, in a watched Sent folder after the outbox logged
the send -- is not filed again: the new UID gets its own row pointing at the
first one's document, contact, interaction and capture item, with
=duplicate_of_id= naming it. A stub is not a match. When the first row has
no document (the outbox kept no bytes), this copy files them.

Addresses that match no contact or lead are upserted into
=mail_unmatched_sender= with a count, the last subject, the display name and
=last_seen_at= (which never moves backwards), unless the address matches
=ignore_patterns=, belongs to =internal_domains=, or the message is bulk: it
carries =List-Id=, =Precedence: bulk=, =list= or =junk=, or an
=Auto-Submitted= value other than =no=. The lookup includes deleted rows,
because the unique index does: a deleted sender is restored and counted.

The unmatched list is =/e/mail_unmatched_sender?dismissed=false=. Each
sender's page has two buttons:

- *Create contact* (=POST /api/v1/mail_unmatched_senders/:id/create_contact=)
  creates the contact, removes the sender row and records interactions for
  up to 500 messages already filed from that address, in one transaction.
- *Dismiss* (=POST /api/v1/mail_unmatched_senders/:id/dismiss=) sets
  =dismissed=. The row stays as an ignore-list entry: later mail still counts
  on it but never lists it again. Clear the flag to undo.

** Capture

A message addressed to the capture address, or sitting in the capture
folder, does not touch the timeline. The capture address is compared
exactly, case aside, in To, Cc, =Delivered-To= and =X-Original-To=. An
untagged capture address also takes its +tag variants (=receipts+toner@= for
=receipts@=); a tagged one never matches its untagged base, so account
=ops@example.com= with capture =ops+receipts@example.com= keeps ordinary mail
on the timeline. A capture address the account's own mail would match is
refused when the account is saved, and a row saved before that check is
refused at sync.

Each attachment is filed as a =document= of kind =receipt= with its SHA-256
=hash= and =extracted_text= from =venture_document_extract_text()= (the same
extractor as an upload: PDFs through poppler, HTML as text, text types as
UTF-8), and handed to =venture_capture_service_ingest_for_organization()=
with source =email=, the subject as title, the sender as vendor, the message
date and the body as notes -- the same path an upload takes, so conversion,
period guards and approvals are unchanged. Inline images referenced by
Content-ID, S/MIME and PGP signatures, calendar invitations (=.ics=) and
TNEF (=winmail.dat=) are not receipts and are skipped. A forwarded message
(=message/rfc822=) is opened: its attachments are receipts too. A message
with no attachment files its body as the receipt: a forwarded message's
HTML or text first, then the message's own text, then its HTML, so an
HTML-only receipt is captured as HTML. An attachment whose content hash
already backs a capture item in the organization is skipped, so a receipt
uploaded by hand and forwarded by mail is one inbox row.

** Outbound on the timeline

When the outbox's delivery sweep records a message as =sent=, it commits
that state first and then, in a separate transaction, records an =email=
interaction with =outbound= set on every contact (or, failing one, lead)
whose email matches a To or Cc recipient, with the single-open-deal rule
applied. The recipients are looked up with a filtered query rather than by
loading every contact. A failure there is logged as a warning and never
rolls back the sent state: the relay already accepted the message, and an
=uncertain= row an operator retries would mail the customer twice. When the
organization has a =mail_account=, the send's Message-ID is also kept on a
=mail_inbound= row (key =outbox:<message id>=), so the copy that appears in
a watched Sent folder is a duplicate rather than a second interaction, and a
customer's reply threads to it. The private text body is never copied.

** Running it

#+begin_src sh
venturectl mail sync                     # every active account in the default organization
venturectl mail sync organization_id=2 limit=10
venturectl mail sync account_id=3        # one account now, ignoring its backoff
venturectl mail contact 12               # unmatched sender 12 becomes a contact
venturectl mail dismiss 13               # unmatched sender 13 is ignored from now on
curl -X POST .../api/v1/mail/sync?organization_id=1
curl -X POST .../api/v1/mail_accounts/3/sync
#+end_src

A sweep syncs the organization's active accounts that are not backing off,
one after another, sharing one message budget and one time budget, and
returns ={"accounts", "messages", "skipped", "deferred", "errors": [{"account",
"error"}]}=: =skipped= counts accounts in backoff or leased elsewhere,
=deferred= says a budget ran out and the next call continues. The account
route returns the same shape for one account. The sweep requires editor
access; syncing one account by id requires the owner, like the account row.
Both refuse =--stage=. The account page carries a *Sync now* button
(=POST /mail_accounts/:id/sync=), which lands back on the page with the
outcome in =last_error=.

Schedule the sweep with the =mail_sync= automation handler, whose arguments
are the organization ID and a message budget from 1 to 1000:

#+begin_src text
pod mail_sync_five = cron->new("*/5 * * * *");
mail_sync_five->on_schedule => venture->mail_sync("1", "200");
#+end_src

It returns ={'accounts', 'messages', 'errors'}=. A failing account is
recorded on the account and backs off by itself; only a sweep that could not
run at all (the module off, a bad argument) fails the rule.

** Transport

=VentureImapClient= is a GInterface (connect, select, list, since, fetch,
fetch_truncated, set_deadline, disconnect). =deps/mail-glib= is sending-only,
so =VentureSocketImapClient= in =src/mail/= is a minimal IMAP4rev1 client
over GIO sockets:

- Implicit TLS or STARTTLS through GTlsClientConnection (certificates
  verified; a =PREAUTH= greeting before STARTTLS is a downgrade and refused).
- =CAPABILITY= after TLS, discarding anything advertised before it.
  =AUTHENTICATE PLAIN= when offered (with SASL-IR when advertised), which
  carries UTF-8 credentials unchanged; =LOGIN= otherwise, unless
  =LOGINDISABLED=, sending a non-ASCII credential as a literal. Buffers that
  held the password or its base64 are wiped.
- =EXAMINE= (read-only; nothing is flagged or moved) reporting UIDVALIDITY,
  UIDNEXT and EXISTS. Folder names are sent as RFC 3501 modified UTF-7
  (=venture_imap_utf7_encode()=).
- Listing pages =UID FETCH a:b (UID RFC822.SIZE)= over 500-UID windows
  rather than one =UID SEARCH= reply that names every UID on a single line.
  A window that finds nothing jumps to the next UID that exists by
  binary-searching =FETCH n (UID)=, so a gap of billions of UIDs costs a few
  dozen small replies.
- =sync_since= binary-searches =FETCH n (UID INTERNALDATE)= over sequence
  numbers, a handful of small replies instead of a =SEARCH SINCE= line.
- =UID FETCH (BODY.PEEK[])=, or =BODY.PEEK[HEADER]= and
  =BODY.PEEK[TEXT]<0.65536>= for an oversized message.
- Lines are read without buffering more than 8 KiB: a server that never ends
  a line is refused after a few KiB, not after it has filled memory.
  Literals larger than 20 MiB are refused before any allocation.
- Usernames, secrets and folder names containing CR or LF are refused so
  they cannot inject a second IMAP command.

The construct-only =allow-plaintext= property exists for the test suite's
scripted server on loopback; no account field reaches it.
=VentureFakeImapClient= is an in-memory mailbox for service tests, with
injectable connect and fetch errors, sizes, internal dates and UIDVALIDITY.
GMime, already a server dependency through mail-glib, parses the fetched
bytes.

OAuth (XOAUTH2 for Google and Microsoft) is not implemented. A future
provider must refresh tokens through the same account-bound encrypted
credential service and preserve completion-time revocation checks; it must
not reintroduce environment credentials. The current IMAP transport uses
passwords or provider app tokens. CalDAV uses its separate typed client and

* Organization-routing verification

Migration =000540_mail_account_binding= checks the metadata-added evidence
columns while allowing the mail module to be absent. Old rows remain
unbound; it never sends or rewrites historical deliveries.

=test-mail-routing= checks organization isolation, missing configuration,
rotation/disconnect/replacement, operator endpoint revocation, unsupported
file/transport settings, literal credentials, caller-thread preparation,
pre-submission persistence and selected-message delivery. The same database
fixtures run on isolated PostgreSQL when
=VENTURE_TEST_ACCOUNTING_POSTGRES_URI= is set. Settings HTTP tests cover
write-only credentials, stale forms and organization administration.

#+begin_src sh
make DEBUG=1 test-one T=test-mail-routing
make DEBUG=1 test-mail-relay
#+end_src

The second command explicitly starts a pinned disposable Mailpit container,
generates a one-day localhost test certificate and requires authenticated
STARTTLS. Two organizations use different usernames, passwords and senders.
A rejected credential rotation in A must not interrupt B; the relay's HTTP
API independently verifies the three accepted messages and their senders.
It needs Fedora packages =podman=, =openssl=, =curl=, =bash= and =coreutils=;
=ShellCheck= validates the runner. It installs no host packages. The runner
stops its container and removes only its three known fixture files on
success; failures retain their directory and propagate a nonzero status.

C callers can use =venture_organization_mailer_dup_schema()= to derive
write-only settings inputs, and =venture_mail_outbox_deliver_one()= to
restrict a deliberate test to its message and exact configuration. The
ordinary outbox claim, veto, retry and uncertainty rules remain shared.
