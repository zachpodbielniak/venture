#+title: Forge vault — built-artifact demonstration

The actual DEBUG =venture= server and =venturectl= below use a disposable
SQLite workspace and a synthetic loopback Forgejo account endpoint. No live forge,
user credential, repository or hosted workspace is contacted. Authentication is
disabled only on this loopback transport fixture; =test-auth= separately checks
authentication/role refusal. Secrets are supplied on stdin and omitted from this
transcript. Configure/test/account refusal, independent organizations, rotation,
webhook revocation and explicit legacy import are exercised through real routes.
See [[file:forge.org][Git forges]] for the credential and host-capability contract.

PostgreSQL ran in schema-isolated disposable databases with fsync enabled on a
tmpfs-backed fixture. These tests establish PostgreSQL behavior and transactional
rollback, not persistent-media durability. One authentication attempt could not
bind its fixture listener; the complete subsequent run passed.

The regression against the record-only credential factory failed before its
fail-closed implementation. New vault tests also caught a shallow JSON copy that
modified caller-owned settings; credentials now copy only declared input fields.
A worker regression reproduced service finalization joining its own thread;
completion now releases the service on the main context after worker cleanup.
The clone regression refused a nonempty destination while the old helper lived
inside it, then passed with the helper beside the checkout. The owned child
process test checks exact askpass authority, neighboring-host refusal, immediate
revocation, immutable retained connection/version and completion before teardown.
The worker HTTP test holds the database transaction lock while an independent
credential-bound request completes, proving that request does not read the DB.

repairs and their tests. No remaining defect was identified in this bounded lane.
