* What this is

clawtilla runs a fleet of AI agents. Each agent can hold its own VENTURE connection -- =venturectl mcp= with its own token -- and clawtilla can mirror the work its agents do into VENTURE tickets. This page is VENTURE's side of that: what to set up here, and which VENTURE feature each part of the integration leans on. clawtilla's side is its =docs/venture-setup.org=.

Nothing here is clawtilla-specific in mechanism: every feature below is an ordinary, documented API any client may use.

* One account, one membership, one token per agent

Every agent is its own VENTURE user, so the audit trail, the activity on every record and every webhook body say *which* agent did a thing.

1. *Create the user*: a global =editor= (or =viewer=, for an agent that only reads -- but a viewer's writes are staged for approval, which a mirroring agent must not be).
2. *Add its organization memberships*: only the organizations it should reach, with the organization role it needs (=editor= for ordinary work).  Made through the API, a membership must say ~"active": true~ -- an inactive one reaches nothing, and =whoami= then lists no organizations.
3. *Then mint its token*, as an administrator, for that account: =venturectl token mint name=scout-agent user=scout expires_in_days=365=. A token keeps the memberships it was minted with: mint *after* the memberships, and mint a new one when they change.
4. Give the token to that one agent only (clawtilla's per-agent =token_file=).

The agent's own token tells it who it is: =GET /api/v1/whoami= answers the actor string (=API token #N=) every audit row and webhook carries for it, its role, its user and the organizations it reaches ([[file:api.org::*Who am I][Who am I]]).

* Forges and repositories, so remotes resolve

clawtilla files a task's work against the repository it is in by asking =GET /api/v1/forge_repo/resolve?url=<remote>= ([[file:forge.org::*Finding a repository from a remote][Finding a repository from a remote]]). For that to answer:

- a =forge= for each forge, with its =base_url= and -- when SSH is on another host -- its =clone_base_url= (an owner sets these; members can read them, never the credentials);
- a =forge_repo= per repository, in the organization the work belongs to. An agent with an editor membership may add one itself.

A remote resolves only to a repository the asking agent can see, so a repository in an organization the agent is not a member of is simply not found.

* What each feature is for

=GET /api/v1/health= lists =features=; clawtilla checks for each before relying on it and falls back otherwise ([[file:api.org::*Features][Features]]).

| Feature | What clawtilla uses it for |
|---------+----------------------------|
| =whoami= | learning each agent's actor and user, to tell its own changes from another's |
| =external_ref= | stamping each mirrored ticket and comment with its task or note id, so a retried create finds the ticket it made (409) and an echo of its own comment is recognised ([[file:tickets.org::*A reference from another system][A reference from another system]]) |
| =idempotency= | =Idempotency-Key= on its creates, so a create that timed out is not made twice ([[file:api.org::*Retrying a write: Idempotency-Key][Idempotency-Key]]) |
| =repo_resolve= | finding the repository a task's checkout came from |
| =webhook_changes= | telling, from an =*.updated= webhook, whether a change touched a field it mirrors |
| =external_runs= | recording each agent run as a run -- tokens, cost, model, branch, pull request -- so the agent budgets, the Runs page and the delivery report count the fleet's work, and a hard-stop budget refuses it ([[file:forge.org::*Runs done somewhere else][Runs done somewhere else]]) |
| =apply_writes_low_risk= | the middle setting for an agent's own VENTURE tools: =venturectl mcp --apply-writes=low-risk= applies ordinary writes and stages money, people, access and deletes for approval ([[file:mcp.org::*The middle setting: =--apply-writes=low-risk=][The middle setting]]) |

* Webhooks, to wake the mirror

clawtilla does not rely on webhooks -- it polls -- but a webhook wakes it early. Point a signed webhook (Settings -> Webhooks, events =ticket.*= and =ticket_comment.*=) at clawtilla's =venture= trigger, with the webhook's secret given to that trigger ([[file:webhooks.org][Webhooks]]). The body names the record and, on an update, the fields that changed; clawtilla fetches the record with the agent's own token.

* The contract (since 0.10.2)

Every answer clawtilla's mirror reads has its shape -- which keys, of which types -- recorded in =tests/fixtures/api-contract/=, and =/auth/clawtilla-contract= fails when an answer no longer matches.  A change that is meant is recorded again with =make contract-fixtures=; clawtilla keeps a copy in its =tests/fixtures/venture/= and checks its reader against it, and its =make check-venture-contract= diffs the two.  A field renamed under the mirror is then a failing test on one side or the other, not a fleet whose tickets quietly stop updating.

* A ticket for a team of agents

clawtilla can take in an =internal=, =todo= ticket given to a team and to nobody. In each organization it first reads its agents' own team memberships, =GET /api/v1/team_membership?user_id__in=…&active=true= -- each agent matched by the =user.id= its token's =whoami= answers -- which say which teams have an agent in them and who; then each of those teams' tickets, =GET /api/v1/ticket?team_id=N&assignee=&external_ref=&status=todo&kind=internal=, paged with =id__gt==, leaving out with =id__not_in== tickets it has already linked to a task whose assignee is not yet written. It gives each ticket to one of the team's agents and writes that agent back as the ticket's =assignee=. Nothing in VENTURE is configured for it beyond the team itself:

- a =team= in the organization the tickets are in (a team belongs to one organization; the same name in two organizations is two teams);
- an *active* =team_membership= for each agent's user -- made through the API, it must say ~"active": true~, as an organization membership must;
- each agent's user an active member of the organization too, since it becomes the ticket's assignee (below).

=assignee== and =external_ref== mean "none" -- null or blank alike. The contract test asserts each list answers exactly what it should (the unassigned team ticket, not one somebody has, one from another system or one in no team; nothing after it by =id__gt= or once left out by =id__not_in=; the agent's active membership, not its inactive one nor a person's in the same team), and records both answers (=ticket-team-list=, =team-membership-list=) and the timeline's =changes.team_id=, which tells clawtilla whether another agent's own account gave the ticket to the team.

* The assignee must be a member (since the assignee picker)

The mirror writes a ticket's =assignee= as the agent's username, the one its token's =whoami= answered. A ticket's assignee must now be an active member of the ticket's organization, so the agent's user needs an active =organization_membership= of the organization the ticket is filed in -- the one its repository belongs to. Without it the create is refused with a 422 (=assignee: "wildebuild" is not an active member of ...=), which the mirror reports as a dead job ("filing the ticket: ...") rather than retrying. Before, the same ticket would have been made and then been unwritable by that agent, whose own token could not update a ticket in an organization it is not a member of. An agent with no VENTURE account is written as no assignee, which is always allowed. Updates are judged only when the assignee changes, so a reassignment to an agent who is not a member is refused the same way; an unchanged assignee never is.

* Who wrote a comment

A ticket comment made through the API records its writer as its =author= (since 0.10.1): =API token #N= for a token, the username for a session.  An author the caller names is kept -- that is how a mail import records the sender.  clawtilla reads it to tell a person's comment from the assignee agent's own.

* What the activity log shows

Every change an agent makes through its token is recorded against =API token #N=, the number =whoami= reported for it, with the actor kind =token=. That string never changes, so the mirror keeps matching on it: a confirmation's =origin.name=, an activity row's =actor=, a comment's =author=. A person reading the record sees whose token it was -- =erin (API token #N)= -- and the JSON carries it beside the key as =actor_username= (=origin.username= on a confirmation), absent when the token or its owner is gone or the reader may not know it. Changes the mirror makes for an agent are made with that agent's own token, so they read the same way.
