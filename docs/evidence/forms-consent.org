#+title: Forms marketing consent demonstration
#+description: Built-server evidence for explicit marketing permission

* Scope

This demonstrates the marketing-consent integration for issue #147 through
an isolated built DEBUG server and its HTTP API. It is not completion evidence
for the remaining forms epic. Authentication was disabled only on the
throwaway loopback instance. AI, plugins and automation were disabled;
no mail or provider request was made. The fixture used synthetic addresses.

The server was built after integrating master at =23f2c0e= and adding the
explicit =form_field.marketing_consent= property and privacy fixes at
=0851fcb=. The binary digest is in
the transcript. The GTest case =/forms/marketing-consent= additionally checks
published wording against an unpublished edit, preserved suppression and
response survival after a refused follow-up.

* Requests exercised

1. Start =build/debug/venture= with a private SQLite database, state
   directory and explicit loopback port; use =--no-ai --no-plugins
   --no-automation=. The port comes from =venture_test_free_port()=.
2. =POST /api/v1/form= with =state=live=, =create_lead=true= and
   =min_fill_seconds=1=.
3. Create required name and email questions mapped to the corresponding
   lead fields. Create an optional =consent= question keyed =news=, labelled
   "Send the monthly newsletter", with =marketing_consent=true=.
4. =POST /api/v1/form/1/actions/publish= with an empty object.
5. Fetch =/pub/form/TOKEN= and read its signed =_vf_t=. Wait more than the
   configured one-second fill interval before each POST; a too-fast submit
   intentionally looks successful while retaining no response.
6. POST JSON with name, email and ticket, first without =news=, then with
   =news="on"= and a different address. Query =/api/v1/marketing_consent=
   after each submission. Assert zero records for the first and one for the
   second, including the published wording and version in its evidence.
