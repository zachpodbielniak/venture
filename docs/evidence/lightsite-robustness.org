* Proven fixes

- Browser HTTP deadline: the new stalled-header/body scenario failed because
  no deadline existed. A 15-second AbortController deadline now covers the
  entire response and releases serialized consent work. Existing consent,
  offline withdrawal and stable-envelope scenarios pass with it. A single
  content-free browser diagnostic names the failure cause.

- Form loader deadlines: stalled fragment headers/body, POST headers/body,
  cross-origin uploads and same-origin XHR uploads all release controls.
  Six scripted transport scenarios pass. The error states that receipt is
  uncertain; the existing payment nonce is retained and no retry is automatic.
- Intake storage classification: a failed site-table read returned 404 before
  the fix. It now returns a sanitized 500 and one cause log. Restoring storage
  permits the same request to succeed. The real HTTP case passes on SQLite
  and PostgreSQL 18.
- Upload storage classification: unavailable storage and an actual kernel
  short-write failure returned 422 before the fix. They now return 503 with
  retry guidance. The child-process write limit leaves no bytes, upload row
  or response; after lifting it, the same request succeeds. OS errors survive
  to the boundary as typed GIO errors. Invalid files still return 422.
- Payment observability: the lost-Checkout-response case failed its expected
  diagnostic before the fix. It now logs a cause and local invoice ID without
  customer data. The existing retry uses retained payment identity. All eleven
  paid-form cases pass, including replay, uncertain transport, delayed payment,
  booking recovery, erasure and capacity checks.
- Account observability: the authority fixture failed its expected validation
  diagnostic before the fix. It now logs stable categories without credentials
  or token names. All existing hosted/token authority checks continue to pass.

* Operational limits and decisions

- Ben/Zach: choose whether ordinary forms need a general final-submission
  idempotency contract. They intentionally accept repeat responses today;
  email/contact limits and private draft tokens are narrower guarantees.
  Browser deadlines cannot prove whether a lost final response committed.
- Provider calls and optional scanner callbacks are synchronous. Stripe has
  per-attempt timeouts, bounded retry counts, backoff/jitter and Retry-After;
  it has no total wall-clock budget across those waits. A slow provider can
  therefore occupy the request thread beyond the browser deadline. A total
  provider budget/async flow needs a separate decision; no database work was
  moved to a background thread in this pass. Scanner adapters must bound their
  external calls; the default path invokes no external scanner.
- Database failures fail closed. These checks cover failed reads and restoration,
  retained replay after application reconnect (existing attribution test),
  failed file writes and cleanup. They do not claim automatic reconnect or
  replay after an ambiguous commit, power-loss durability, or exhaustive
  host-wide disk exhaustion. Restore database availability and restart Venture
  if its connection was lost; retry retained operation identities.
