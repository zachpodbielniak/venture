* What this is

A transcript of =docs/evidence/ocr-demonstration.py= driving a real
=build/debug/venture= over HTTP, exactly as an operator would: a private
config, a private state directory, a free port taken from the OS, the
first-run owner login, and the ordinary =/api/v1= record, capture and
generated-action routes.

The engine is a fake =tesseract= — a shell script under the scratch root that
answers =--version= with a stable version string, records its real argument
vector, fails on demand and otherwise prints fixed text. This is the same
technique =tests/test-ocr.c= uses. The PNG and PDF fixtures are generated with
python =cairo=, which is how =tests/test-ocr.c= generates them with the C cairo
API; the driver refuses to run if python =cairo= is not importable rather than
substituting a different fixture. There are no checked-in OCR fixture files in
=tests/=, so nothing was reused from there.

The server the run used was linked against Poppler and GdkPixbuf
(=ldd build/debug/venture= shows =libpoppler-glib.so.8= and
=libgdk_pixbuf-2.0.so.0=), so the raster/PDF dependency chain is present and
the PDF page is really rasterised; the documented refusal for a build without
them is not the path taken here.

(=venture_capture_service_ingest_for_organization=, =src/capture/venture-capture-service.c:131=).

when the batch later finds the middle document's original gone, that earlier
pending job is retained and a *new* failed job records the missing original.

* Limitations

Repeated from the transcript, which prints them itself:

- No real Tesseract, no language pack and no real scanned receipt. The engine
  is a shell script that answers =--version= and prints fixed text, exactly as
  =tests/test-ocr.c= does. Recognition quality is therefore not demonstrated;

- Restart resumability, the 30 s process deadline, active cancellation of a

  covered by =tests/test-ocr.c= and are not re-proved here.
