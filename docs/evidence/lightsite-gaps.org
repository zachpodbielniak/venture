* Validation and limits

Targeted checks: 103 forms tests, 113 Venture Stripe tests and 21 migrations,
including the owned PostgreSQL migration fixture. stripe-glib's complete DEBUG
unit and owned stripe-mock integration suite passed; the final edge suite also
passes caller cancellation. The full run on =7442c34= passed 152 of 153 binaries; Stripe stopped at its
old hardcoded dependency-revision assertion. Commit =5c732f3= updates only
that expected revision to the published =ad43580=. Rerunning the Stripe binary
passed all 113 tests, and the litter, version, foreground-demo and clock-demo
checks passed. Thus all 153 DEBUG binaries are green after one complete run
and one targeted repair rerun; the complete build was warning-free.
There were 22 optional test skips. The source remained fixed during each run.

The provider budget applies to each Stripe operation across its attempts, not
an entire multi-operation checkout workflow. Trusted custom transports and
in-process scanner callbacks cannot be forcibly preempted; their contracts
require prompt return. Use the default transport and external scanner for the
bounded paths. No antivirus engine is bundled. Legacy clients omitting a form
identity remain non-idempotent. Existing public availability and rate checks
still precede receipt replay. Intermediate draft mutations are not made into a
general retry protocol. Erasure retains only an unlinked consumed-identity
hash, preventing an old accepted request from recreating erased answers.
