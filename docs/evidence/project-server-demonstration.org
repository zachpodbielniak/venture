* Unresolved ordinary receipt boundary

Without =--precise-receipts=, the same artifact and final script fail in the
fixed-progress scenario (exit 1). A generated invoice stores an issue instant
later than midnight; a receipt entered using that same calendar date is
refused by the strict source-event chronology guard:

#+begin_example
AssertionError: /api/v1/payment: HTTP 422: {
  "error" : "validation",
  "message" : "VentureSettlementService: The date must not precede the source event",
  "code" : 5
}
#+end_example

This is a concrete daily-workflow blocker, reported to the root integration
lane for repair. The diagnostic success above must not be treated as resolving
it. The driver's default keeps ordinary date-only inputs; final qualification
must pass without the workaround. Every receipt attempt additionally verifies
that a prior-calendar-day payment is refused and leaves no payment record.
