#+title: Multi-page forms demonstration

* Built server, keyboard input

Chromium 153 through Playwright, a disposable SQLite instance on loopback,
synthetic addresses, no AI, plugins or automation. The server's normal public
HTTP routes handled every step. A three-page form asked for name, email and
consent. The embed host was a separate HTTP origin. Tab, typing, Space and Enter
were the only input actions; assertions inspected the DOM and stored responses.

A repeated email deliberately caused a server-side final-validation error.
Both the loader and the script-free hosted form returned to page 2 and focused
the error summary. Correcting the email and continuing created one response,
not a response for each attempted submission.

* Automated markup checks

The forms GTest suite checks every intermediate rendering, token tampering,
replay, attempts to alter earlier answers, expiry, privacy export/erasure and
absence of audit/business signals for unfinished pages. The all-question-kind
fixture excludes structural breaks; the multi-page test exercises those.
axe-core in jsdom checked both fixtures (colour contrast excluded there):
