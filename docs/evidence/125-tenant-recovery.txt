The two source stacks and separate empty recovery destination use distinct
rootless Podman networks, application processes, persistent PostgreSQL volumes,
database roles and state/configuration roots. No existing tenant is accepted.
The actual DEBUG application uploads the attachment and creates company,
accounting, bank-binding, document and capture records. A foreign source
session receives 401 from its neighbor. The application is stopped before the
archive is created; decrypted archive identity/image/version/digests are checked
before any destination write. Restored rows are compared before startup can
legitimately update operational state. The restored application then starts,
accepts local login and reads its retained company/provider settings.

The driver checked the restored rows and the transcript records its result.
No credential, key file, archive plaintext or private business data is published. This is a
small synthetic recovery proof, not a scale test, cross-host off-site proof,
provider-authentication proof or the final hosted-boundary security review.

Failure evidence:
- Removing the container tenant-label comparison fails the ownership case.
- Requiring a literal sha256: prefix fails against real Podman image IDs; the
  regression now accepts either representation of exactly the same digest.
- The deterministic GTest invokes real GnuPG, tar, permissions, file locking,
  archive publication and restore staging with only Podman transport replaced.
  It rejects tampering/wrong keys, authenticated traversal and link payloads,
  wrong workspace IDs despite matching local slugs, live apps, privileged DB
  roles, nonempty targets, wrong mounts, failed dumps and failed restore.
- Bash syntax and ShellCheck pass. The real DEBUG-style GTest passes and removes
  its successful fixture using venture_test_remove_tree().
