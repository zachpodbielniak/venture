#+title: Forms scheduling and response-limit demonstration

* Scope

Built DEBUG server, isolated SQLite database and loopback listener, synthetic
email addresses, authentication disabled on the fixture only. AI, automation
and plugins were disabled. No external provider was contacted.

The run creates a live published form with a required email question and
=unique_email_field=email=. Its opening time initially lies in the future.
API updates then open it, close it after a signed ticket was issued, reopen
it and set a total cap of two. Two HTTP clients submit concurrently for the
remaining place. The transcript records assertions against actual HTTP
responses and the final stored response count.

This is evidence for the schedule, total-cap and email-limit portions of #148.
Personal-link and contact limits were completed subsequently; see
[[file:forms-prefill.org][the prefill and personal-link demonstration]] and =/forms/personal-links=.
Exact boundary times and stale form objects are additionally covered by
=/forms/schedule=.
