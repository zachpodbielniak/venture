#+title: Receipt and supplier-invoice capture
#+description: Inbox rows that become expenses or vendor bills through existing services

* An inbox row is not yet a book

The =capture= module requires =finance= and suggests =payables=. It owns
=capture_item=. Upload, email and scan land here as =receipt= or
=supplier_invoice= rows in status =inbox=. Conversion is the only writer
that creates the destination.

A receipt becomes an =expense= through the ordinary expense save, so
automatic journals, period guards and uniqueness still apply. A supplier
invoice becomes a draft =vendor_bill= plus one =vendor_bill_line=; approval
and payment stay on =VenturePayablesService=. Rejection keeps the inbox
evidence without a book entry.

#+begin_src sh
venturectl capture ingest kind=receipt title="Toner" 'amount=12.50 USD' occurred_at=2026-01-15 vendor="Office Supply"
venturectl capture convert 1 as=expense category=office
venturectl capture convert 2 as=vendor_bill company_id=1
venturectl capture reject 3 reason=personal
#+end_src

Capture ingestion through the API files the item under the active organization. =venture_capture_service_ingest_for_organization()= provides that explicit scope to other callers; the original ingest API uses the configured default organization. Conversion preserves the captured item's organization for the expense or supplier bill.

The inbox button "Snap a receipt" opens =/capture/file=. An owner uploads or photographs a receipt or a supplier bill there, with a bounded preview before the file is sent so the form remains usable. The server stores the bytes as a document and an inbox row for the active business, or the default business when none is selected. The form does not ask for status, source, or result fields. Accepted files are images other than SVG, including HEIC, and PDF, up to the 15 MB attachment limit.

=/capture/items/:id= shows the filed picture and offers "File it as an expense" or "File it as a supplier bill". Both posts call =venture_capture_service_convert()=. A supplier bill still needs a matching vendor company, and a missing one is a page error. The picture itself is =/capture/items/:id/photo=, served only when the stored type is an allowed image or PDF, and only for the same business. A signed-out request for any of these pages redirects to =/login=.

Inbound mail feeds the same path: the =mail_sync= module files each
attachment of a message sent to the account's capture address (or found in
its capture folder) as a document and ingests it with source =email=,
skipping any attachment whose content hash already backs a capture item.
Attachments inside a forwarded message count; inline logos, signatures,
invitations and =winmail.dat= do not. A message without attachments is its
own receipt, filed as HTML when that is all it has. Text is extracted with
=venture_document_extract_text()=, the extractor an upload uses. See
[[file:mail.org][mail]], section Inbound, Capture.

* Optional local OCR

With =modules.ocr.enabled=true=, ingesting a filed document also queues a
local extraction job. OCR is off by default; ordinary capture and vision
continue when it is disabled. The capture inbox offers the metadata-derived
bulk extraction action. Jobs and frozen batches advance one page at a time,
retain failures and can be retried, cancelled or resumed. Review the job's
text on its document before using it with the existing AI or conversion
workflow; OCR itself never posts accounting entries.

See [[file:ocr.org][Local OCR and capture review]] for image/PDF support,
language packages, process and batch limits, provenance and correction
protection. =document.path= is assigned by the trusted upload/mail filing
service; generic forms, imports and API writes cannot select a filesystem
path or transfer an existing attachment to another organization. Existing
valid originals remain usable. Re-upload an attachment when its historical
path is ambiguous across organizations; no migration rewrites that history.
