#+title: Marketing — built-artifact demonstration

These verbatim transcripts run the DEBUG-linked Venture test artifact with
synthetic organizations and recipients. The HTTP case starts the actual
Venture web server and invokes the built =venturectl= using a disposable
operator API token; credentials and private links are not printed. The SMTP
case uses a real local scripted relay to inspect the generated message wire.
No external recipient is contacted. Reconnect means a closed and reopened
application database, not a claim about physical power-loss recovery.

Reproduce with =make DEBUG=1=, =make DEBUG=1 plugins= and
=make DEBUG=1 build/debug/tests/test-marketing build/debug/tests/test-mail=,
then run the commands printed below from the repository root. The same
marketing suite supports per-fixture isolated PostgreSQL through
=VENTURE_TEST_ACCOUNTING_POSTGRES_URI=. The documented management decisions
and limitations are in [[file:marketing.org][Marketing sends]].

* Review and validation

Local =skill-review= checked the demonstration before the final diff and
repeated the review after repairs. Regressions reproduced and repaired an
unrelated-session capability refusal, UTC daily tracking duplication,
reentrant withdrawal immediately before transport, disabled-module withdrawal,
reserved consent identity collision, dedupe rewriting approved subjects, and
the PostgreSQL dedupe parameter error, and a withdrawal during a later mutable
outbox hook. Existing immutable sequence suppression
was reused and pinned rather than replaced with a second opt-out policy.

cleanup check. Related checks cover the two outbox scheduling/cancellation
