#+title: Marketing, sales, phone and text parity — the gap audit

This page is lane 0 of the epic "marketing, sales, phone and text that
replace separate tools", worked on =feat/191-marketing-sales=. It compares
what Venture already does against three kinds of tool a small business
otherwise pays for separately: an email-marketing tool (designed campaigns,
audiences, journeys, deliverability), a CRM (pipelines, scoring,
assignment, booking, mailbox sync) and a phone/text tool (calls, texts and a
shared inbox). The phone and text lane names its first connectors: a 3CX PBX
for calls and VoIP.ms for SMS/MMS.

Each table below is one lane of the epic, one row per capability. *Venture
today* is =have=, =partial= or =missing=. A =have= or =partial= cites the
code that was read to confirm it, not only the module page. Paths are
relative to the repository root. *What the later lane builds* is the gap
that lane closes; nothing here re-implements what already exists.

* How work lands here

- Take one lane. Branch from =feat/191-marketing-sales=, not =master=.
- Tests first, then the change, then this page: move the lane's rows to
  =have= with the commit that closes them.
- Lanes run in order 1 to 9; each lane builds on the previous lane's
  services rather than adding a parallel path.

* Where outgoing email is built today

Every outgoing message is an unsaved =VentureMailMessage= handed to
=venture_mail_outbox_enqueue()= (=src/mail/venture-mail-outbox.h=). Each
sender composes its own subject and bodies inline; there is no shared
renderer, layout, brand or preview step. The =mail_template= record
(=src/mail/venture-mail-records.c=: name, subject, text body, HTML body with
={field}= substitution, rendered by =venture_mail_template_render()= and
=venture_mail_template_render_values()= in =src/mail/venture-mail-template.c=)
is the only template mechanism.

| Email kind | Function that builds it | Body today |
|------------+-------------------------+------------|
| Invoice | =venture_mail_send_invoice()= and =invoice_html()=, =src/mail/venture-mail-consumers.c= | =invoice= template text plus a hand-built HTML table, PDF attached |
| Quote | =venture_quote_mail_enqueue()=, =src/quotes/venture-quote-mail.c= | plain text; acceptance link in the private text body, so no HTML part |
| Quote acceptance confirmation | =venture_mail_confirm_money()=, =src/mail/venture-money-mail.c= | text and minimal HTML |
| Overdue reminder | =render_message()= and =send_step()=, =src/dunning/venture-dunning-service.c= | organization =mail_template= per step; private HTML twin for the pay link |
| Payment receipt | =send_receipt()=, =src/documents/venture-financial-documents.c= | plain text, PDF attached |
| Subscription notice | =queue_notice()=, =src/billing/venture-billing-service.c= | plain text |
| Collection notice | =queue_notice()=, =src/recurring/venture-recurring-service.c= | plain text, empty HTML |
| Report pack | =enqueue_output()=, =src/report/venture-report-pack-delivery.c= | built-in template, files attached |
| Booking confirmation | =booking_mail()=, =src/calendar/venture-booking-reservations.inc= | private plain text |
| Form confirmation, opt-in, resume link | =forms_queue_confirmation()= (=src/forms/venture-forms.c=), =forms_optin_store()= (=src/forms/venture-forms-optin.inc=), =forms_resume_save()= (=src/forms/venture-forms-resume.inc=) | plain text |
| Portal invitation | =venture_portal_service_send_invitation()=, =src/portal/venture-portal-service.c= | private plain text |
| Account welcome and password reset | =venture_mail_save_user()=, =src/mail/venture-mail-outbox.c= | plain text |
| Marketing campaign | =make_recipient()=, =src/marketing/venture-marketing-audience.inc=, via =venture_marketing_service_preview()= | operator-written text and HTML, frozen per recipient, unsubscribe appended |

=src/mail/venture-smtp-mailer.c= always sends a text part (empty when the
sender gave none) and drops the public HTML when a private text body is set.

* What later lanes build

Only the =partial= and =missing= rows above.

- Lane 1: done (see its table).
- Lane 2: AI design from a brief; edits by words with undo; grounded plain
  fallback; block builder; brand settings; saved designs beside text
  templates; reusable sections; hosted images; video block; client
  rendering.
- Lane 3: done (see its table and [[file:deliverability.org][Deliverability]]). Only the
  =generic= feed adapter ships; a named provider's shape is a new adapter.
- Lane 4: tag operations; behaviour segments; topic preferences; journey
  branches; named triggers that enrol; A/B with winner; recipient local
  time; resend to non-openers.
- Lane 5: drag and drop on the board; AI lead scoring; token mailbox
  sign-in and replying from the timeline.
- Lane 6: telephony connector with 3CX and VoIP.ms; click-to-call; call
  logging from the PBX; inbound match and missed calls; two-way SMS;
  inbound webhook; STOP/HELP, consent and quiet hours; real text steps.
- Lane 7: conversation thread per contact; assignment; status.
- Lane 8: inbound judgements on messages; auto-replies; call summaries;
  drafts and next step; per-rule auto-send; consent and quiet hours;
  message log with reason; one off switch.
- Lane 9: defaults; one settings screen; one settings API with audit.
