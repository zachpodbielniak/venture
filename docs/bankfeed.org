#+title: Bank feeds
#+description: Pluggable statement feeds that write bank_transaction through the existing match import

* Bank feeds

The =bankfeed= module is opt-in and requires =banking=. Set
=bankfeed.enabled: true=. The Teller factory is registered without credentials;
plugins can register other providers. =VENTURE_BANKFEED_TELLER_KEY= is no
longer read. An unconfigured connection fails closed even if that old
installation variable is present. Production HTTP uses
=venture_bank_feed_transport_get_async= with a =GCancellable=; database
writes stay on the completion context.

A =bank_connection= row links one provider account to its =bank_account=
for statement evidence. Its organization, provider, remote account and local
bank identity are fixed after creation. Create a different connection when
the account changes; never rewrite the identity of retained imports.
The destination bank must belong to the connection's organization. Derived
connection keys include organization, so independent businesses may use the
same remote account identifier without a collision. Migration 550 backfills
these keys atomically; an inconsistent historical identity refuses migration
rather than discarding an account.

* Organization settings

Open =/bankfeed=, link the bank account, then choose =Settings= on that row.
Organization owners and administrators can configure, rotate, test or
disconnect this connection at =/bankfeed/:id/settings=. The form is generated
from the provider's write-only schema. Supply the complete settings on every
rotation; credential fields are never populated with saved values. Stale
binding IDs or versions refuse the save. Ordinary editors cannot manage
provider credentials.

For Teller, supply =access_token= and =environment= (=sandbox=,
=development= or =production=). Development and production also require the
application's =certificate= and =private_key= as PEM text. These values are
encrypted together through [[file:integrations.org][organization integration storage]];
there are no credential files, environment lookups or caller-selected API
hosts. The TLS client identity is built in memory. The sandbox permits no
certificate because it contains synthetic data; Teller requires mTLS for
end-user data, as described in its
[[https://teller.io/docs/api/authentication][authentication contract]].

=Sync and test= uses the ordinary sync operation for the previous 30 days:
it verifies provider access and imports new statement rows, reporting their
count. It is not a dry run and does not post a journal. Repeated imports use
the existing statement deduplication. A saved configuration is not a claim
of successful provider access. TLS/authentication refusals are errors, never
reasons to borrow an installation token or another organization's account.

Each bank connection has its own encrypted binding, keyed by its stable UUID
within its organization; multiple enrollments do not share credentials.
A sync resolves the binding and exact version before network I/O, then checks
that version again before importing the response. Rotation, disconnect or
revocation during a request prevents the stale result from being written;
retry deliberately using the current settings. Disconnect retains previously
imported statement evidence. A replacement receives a new integration ID.

For migration from installation settings, an administrator must explicitly
select each bank connection and enter its authorized credentials. Venture
never guesses which organization owned the old token. Keep the integration
master key separately backed up as described in the integration guide.

* Providers

=VentureBankFeed= is a GInterface with a registry, the same shape as
posting rules. A provider's optional =prepare= hook builds an immutable
client from one resolved credential snapshot; =dup_schema= supplies its
write-only settings schema. The service performs authorization, encryption
and version checks for every factory. A plugin adds these hooks to join the
same settings/sync workflow. Fully configured feeds injected without a
factory remain a trusted in-process extension/test facility; tenants may
not load arbitrary plugins. The built-in Teller implementation talks through
an injectable transport, and fixture tests use synthetic responses.

Fetch results are imported through =VentureBankMatchService= action
=feed=. That writes =bank_transaction= with the existing external-key
dedupe (organization, bank account, provider transaction id). A second
sync of the same window creates zero new rows. A failure rolls back the
batch, including the connection's last-sync stamp.

* Scheduling

Automation can call the same function the page uses:

#+begin_src text
pod bank_hour = cron->new("0 * * * *");
bank_hour->on_schedule => venture->bankfeed_sync("1");
#+end_src

=venturectl bankfeed sync ID= and =POST /api/v1/bankfeed/:id/sync= take an
optional =period_start= / =period_end=. The web page is =/bankfeed=.

* Provider lifetime and asynchronous contract

Every provider used by service sync implements =fetch_async= and returns a
=GTask= containing an owned array of owned JSON objects. Synchronous-only
plugins are refused by that path. Completion and database application stay
on the caller's main context. Sync and scheduled-sync entry points dispatch
the same async operation while iterating that context. Providers must allow
reentrancy during this wait. All actor strings are copied before returning.

The HTTP transport refuses redirects, including redirects carrying custom
Shopify authorization headers. Its synchronous adapter dispatches async I/O;
no request or scheduled import blocks the event loop on a socket read.

Connection records select the legal entity for each sync, and their bank
account must belong to that same entity. The web handler also requires the
connection to belong to the active organization. Scheduled sweeps filter
connections by the organization supplied to the automation action.

The Teller adapter sends inclusive =start_date= and =end_date= filters, with an escaped account path segment, as specified by the [[https://teller.io/docs/api/account/transactions][Teller transactions API]]. Reversed date windows are refused. It does not request a =count= limit, so Teller returns the complete filtered list.
