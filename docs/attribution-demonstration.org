#+title: Attribution — built-artifact demonstration

These are verbatim transcripts from the DEBUG-linked Venture test artifact,
using synthetic organizations, site visitors and invoices. The transport cases
start the actual Venture web server; the report surface case also executes the
built =venturectl= and prints its JSON. Its disposable loopback instance disables
authentication only for transport verification. The separate authority case
uses real organization membership, and the full =test-auth= suite verifies the
settings routes refuse anonymous callers. No external visitor, customer,
Lightsite deployment or model provider is contacted.

Reproduce with =make DEBUG=1= and
=make DEBUG=1 build/debug/tests/test-attribution=, then run the exact commands
below from the repository root. The Node browser harness uses built-in modules
and deterministic network/storage fixtures; missing Node fails, never skips.
PostgreSQL runs use independent schemas through
=VENTURE_TEST_ACCOUNTING_POSTGRES_URI=. Reconnect closes/reopens the application
database; it does not simulate physical power loss. Provider intake uses the
versioned signed contract, not a claim that a remote forwarder was deployed.
The scope and integration instructions are in [[file:attribution.org][First-party attribution]].

The sections correspond to the lane's seven acceptance items: configured
ownership; explicit analytics consent; bounded durable ingestion; verified form
intake; canonical CRM history; defined financial measures; and usable built
surfaces. Upgrade verification is included separately.
